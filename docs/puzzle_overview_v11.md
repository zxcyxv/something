# v1.1 세 퍼즐의 전체 풀이 흐름

160k 체크포인트, 원래의 12퍼즐 FP32 배치에서 정상 실행을 재생했다. 세 퍼즐 각각 완답 블록 T의 전후 128블록, 총 257블록을 저장했다. 정답은 관측값 계산에만 사용했다.

뷰어는 데이터를 포함한 독립 HTML이며 각각 약 97–101 MB다. 최신 브라우저에서 열면 별도 서버 없이 동작한다. 범위는 ±16/32/64/128블록으로 바꿀 수 있다. 보드에서 받는 셀, 연결 행렬에서 받는 셀과 보내는 셀을 선택한다. 행렬의 세로가 받는 셀, 가로가 보내는 셀이다. 모든 셀 번호는 r1c1부터 행 우선 순서다.

정적 어텐션 PNG는 기존에 해부했던 head 3의 **전체 81×81 연결**을 보여준다. PDF의 후속 페이지와 뷰어는 8개 헤드를 모두 포함한다. 부호가 상쇄되는 헤드 평균은 사용하지 않았다. 시간과 헤드 사이에서 색 범위를 고정했다. G와 W는 큰 대각 성분 때문에 작은 비대각 성분이 옅게 보일 수 있다. 뷰어에서 셀을 선택하면 연결 수치를 확인할 수 있다.

## 전체 보드에서 관측한 변화

각 칸은 **오답 셀 수 / 중복 충돌 쌍 수**다. 충돌은 같은 행·열·박스에 속하는 두 셀의 유효한 예측 숫자가 같을 때 세며, 여러 조건을 동시에 만족해도 한 쌍으로 센다.

| 퍼즐 | T | T−128 | T−16 | T−1 | T | T+128 |
|---|---:|---:|---:|---:|---:|---:|
| 58 | 4212 | 47 / 13 | 24 / 24 | 1 / 3 | 0 / 0 | 0 / 0 |
| 209 | 3778 | 40 / 3 | 14 / 6 | 1 / 2 | 0 / 0 | 0 / 0 |
| 230 | 3649 | 33 / 15 | 13 / 12 | 1 / 2 | 0 / 0 | 0 / 0 |

- **마지막 한두 셀의 문제로 시작하지 않았다.** 이 관측 구간의 시작에는 세 퍼즐 모두 여러 행과 박스에 걸쳐 수십 칸이 틀려 있었다.
- **중복 충돌 감소와 정답으로의 접근은 같은 지표가 아니다.** 퍼즐 209는 T−128에서 오답 40칸, 충돌 3쌍이었다. 이후 T−38에서는 오답이 17칸으로 줄었지만 충돌은 26쌍이었다. 적어도 이 정상 궤적은 매 블록 충돌을 줄이는 단조로운 교정이 아니다. 충돌이 적은 상태가 정답에 가까운 상태라는 해석도 이 두 시점과 맞지 않는다.
- **세 퍼즐 모두 T 이후 128블록 동안 예측 숫자가 한 칸도 바뀌지 않았다.** 관측 구간 내에서는 모든 원래 단서도 유지했다. 이는 이 유한 구간에 대한 출력 안정성 관측이다.

## 출력 안정성과 내부 상태의 변화

T와 T+128 사이의 행렬 차이를 전체 8×81×81 원소에서 RMS로 계산했다.

| 퍼즐 | aψ | aβ | agree | W |
|---|---:|---:|---:|---:|
| 58 | 0.130965 | 0.168245 | 0.260478 | 0.114410 |
| 209 | 0.131182 | 0.168917 | 0.262844 | 0.113003 |
| 230 | 0.129895 | 0.167607 | 0.254555 | 0.113858 |

따라서 이 세 사례에서 **정답 출력이 유지된다는 것은 내부 어텐션과 기억이 정지했다는 뜻이 아니다.** 이 수치만으로 내부 진동이 감쇠했는지, 주기 운동이 남았는지, 천천히 이동하는지는 판정하지 않는다. 정상 궤적 그림 자체로 W나 STDP의 인과적 역할을 확정하지도 않는다. 기존 개입 결과와 연결할 때에도 순간 읽기의 효과와 장시간 상태 변화의 효과를 구분해야 한다.

## 화면의 수치와 forward 대응

블록 k의 왼쪽 보드는 들어오는 h[k−1], 오른쪽은 읽기를 마친 h[k]를 같은 분류기로 해독한 결과다. 각 블록의 argmax 숫자는 forward에 다시 입력하지 않았다.

1. 들어온 h에 MLP와 입력 임베딩을 더한 q에서 주소 u와 값 v를 계산한다.
2. aψ, aβ, agree를 계산하고 `G = gain × aβ × agree`를 만든다.
3. `W[k] = (1−η) W[k−1] + η G[k]`로 현재 쓰기를 적용한다.
4. `J = (1−λ) aψ + λ W[k]`로 값을 읽는다.
5. 잔차 q에 읽은 값을 더하고 phi와 분류기를 거쳐 오른쪽 보드의 로짓을 얻는다.

뷰어의 W는 **현재 쓰기 후** 값이며, ΔW는 실제 `W[k]−W[k−1]`이다. 행렬의 수치는 signed coefficient이고 softmax 확률이 아니다. 선택한 연결의 로짓 차이 기여는 실제 출력 정규화값을 사용해 계산한다. 다른 연결과 잔차를 포함한 전체 로짓 또는 반사실적 개입 효과와 동일하지 않다.

## 재현과 검증

```bash
python lt/capture_puzzle_overview_v11.py --before 128 --after 128
python lt/build_puzzle_overview_v11.py
```

- 캡처된 모든 블록에서 배치 전체 12개 퍼즐의 예측이 기존 baseline과 일치한다.
- 잔차와 전체 헤드의 메시지로 실제 9개 숫자 로짓을 재구성한 최대 절대 오차는 세 사례 모두 `1.90735e-5`다.
- 원본은 각 퍼즐 디렉터리의 `states_fp32.npz`에 FP32로 저장했다. 뷰어의 행렬만 int16으로 양자화했다. 행렬별 최대 표시 오차는 `viewer_build.json`에 기록했다. 시간·보드 지표는 양자화하지 않았다.
- `macro_summary.json`에 표와 행렬 변화의 원자료를, `viewer_validation.json`에 브라우저 조작 및 기존 연결 수치와의 대조 결과를 저장했다.
