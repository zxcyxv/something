# v1.71: QR 없는 공유 주소 투영

2026-09-27. v1.7의 공유 복소 주소 투영 `W_C`를 직접 학습하는 선형행렬로 바꾼다.
목적은 QR의 축 부호 선택과 행직교 제약을 제거한 조건에서 학습을 확인하는 것이다.
학습 안정성 개선이나 과거 급락의 해결은 아직 입증하지 않았다.

## Kaggle 단일 셀: 새 학습과 재개

`lt/기존캐글코드.py`의 실제 동작하는 단일 셀 실행·학습 하네스를 기준으로
[lt/train.py](../lt/train.py)를 작성했다. 이 파일 전체를 Kaggle의 파이썬 셀 하나에
붙여넣고 실행한다. 기존처럼 `sudoku_lt_1k.npz`를 Kaggle Input에 연결하거나
맨 위 `CFG['data_npz']`에 파일 경로를 지정한다. 외부 저장소 import나 별도 셀은 필요 없다.

기존 셀의 모델은 값 이력과 지연 읽기를 사용했으므로, 모델 부분은 v1.71로 교체했다.
주소 이력 Z, 학습되는 beta, 갱신한 W를 같은 블록에서 읽는 순서, post MLP를 유지한다.
새 학습에서는 QR 없이 W_C를 무작위 초기화한 뒤 직접 학습한다.
현재 파일 맨 위 `CFG`는 사용자가 지정한 다음 Kaggle 입력에서 **44,919스텝 재개**를
하도록 설정되어 있다. 아래의 380k 변환 실험과는 별개다.

```python
CFG['data_npz'] = '/kaggle/input/datasets/jrjinwoo/sudoku-lt-1k/sudoku_lt_1k.npz'
CFG['resume_from'] = '/kaggle/input/datasets/jrjinwoo/lt-v171-44919/step_44919.pt'
```

처음부터 학습하려면 `resume_from=None`, `require_resume=False`로 바꾸고
기존 체크포인트가 없는 새 `out_dir`을 지정한다. 재개가 반드시 필요한 실행에서는
`require_resume=True`로 지정하면 체크포인트 누락 시 새 학습을 시작하지 않고 중단한다.
명시한 `resume_from`은 출력 폴더의 체크포인트보다 우선한다.

| 설정 | 기본값 |
|---|---|
| 정밀도 | `amp_dtype='bfloat16'` — BF16 autocast, 파라미터·optimizer는 FP32 |
| 정밀도 선택 | `bfloat16`, `float32`, `auto`; auto는 지원 GPU에서 BF16, 나머지는 FP32 |
| beta 초기화 | `beta_init_mean=1.5707963267948966`, `beta_init_std=0.0`: 모든 성분을 +pi/2로 시작하고 이후 학습 |
| 메모리 | `activation_checkpoint=True`; 블록 재계산, 세그먼트 안의 gradient는 유지 |
| GPU | `num_processes='auto'`; 기존 셀처럼 별도 Python/torchrun 프로세스 |
| 학습 | 배치128, 16세그먼트 × 8블록, 50,000에폭, 실제390,600업데이트 |
| 학습률 | `1e-4`, 처음2,000스텝 warmup, 이후 상수 |
| 출력 | `/kaggle/working/lt_v171` |
| 정규 평가 | 250에폭마다, held-out2,048문제, EMA, 16세그먼트 |
| milestone | 10,000스텝마다, 전체에서 고정512문제, EMA, 128세그먼트 |
| 세션 종료 | `max_hours=11.5` 또는 중단 요청 시 완료한 업데이트 경계에서 저장 |

milestone에서는 세그먼트별 셀 정확도, 퍼즐 완답 수·비율, 답 변경률을 모두 출력한다.
학습 지평·최고 완답·최종 세그먼트 요약도 화면과 `train.log`에 함께 남긴다.
`milestones/`에는 해당 체크포인트와 `extrap_step_N.txt`, `.json`, 누적 `extrap_results.jsonl`을 저장한다.
평가 문제 수512는 여러 GPU를 합친 전역 개수다.

`resume_from=None`일 때 새 출력 폴더에서는 step0부터 시작한다. 같은 셀을 다시 실행하면 그 폴더의 마지막
v1.71 체크포인트에서 raw 가중치, optimizer, EMA, 각 rank의 h/W/Z·현재 퍼즐·RNG·데이터 위치를 복원한다.
새 실험을 시작하려면 `out_dir`을 바꾼다. 세션을 바꿀 때에는 이전 output을 Input에 연결하고
`resume_from`에 체크포인트 파일 또는 폴더를 지정한다. `max_steps`는 추가 횟수가 아닌 절대 종료 스텝이다.
일반 체크포인트는 `keep_last=2`로 최근 두 개를 유지한다. `milestones/`의 milestone
체크포인트는 별도로 보관되며 이 삭제 규칙의 대상이 아니다.

T4처럼 native BF16을 지원하지 않는 GPU에서는 `amp_dtype='auto'` 또는 `'float32'`를
선택한다. BF16을 명시했는데 지원되지 않으면 오류로 종료하며 FP16으로 바꾸지 않는다.

로컬 CLI는 `--config` JSON을 전달하며, 이 경로는 맨 위 Kaggle용 `CFG` 대신
내장 `DEFAULT_CFG`에 JSON 설정을 덮어쓴다. 예를 들어 로컬에서 새 학습을 시작할 설정은:

```json
{
  "data_npz": "data/sudoku_lt_1k.npz",
  "out_dir": "runs/v171_scratch_new",
  "resume_from": null,
  "require_resume": false,
  "amp_dtype": "bfloat16",
  "max_hours": 11.5
}
```

위 내용을 `run_config.json`으로 저장하고 `python lt/train.py --config run_config.json`으로
실행한다. 로컬 재개에서는 `resume_from`을 전체 `.pt` 파일 경로로 바꾸고
`require_resume=True`로 설정한다. 체크포인트에는 raw/EMA·optimizer·carry·RNG·데이터 위치가 필요하다.

beta 초기화는 새 학습에만 적용한다. 기존의 `N(0, 0.5²)`로 시작하려면
`beta_init_mean=0.0`, `beta_init_std=0.5`로 설정한다. 재개 시에는 저장된 beta와
초기화 설정을 복원하며, 옵션이 없던 체크포인트는 기존 0 중심 초기화로 기록한다.
같은 seed에서 초기화 설정만 바꾸면 beta 외의 초기 가중치와 난수 상태는 같다.

`cos(dphi + pi/2) = -sin(dphi)`이므로 +pi/2 초기화는 반대칭 쓰기 커널에서
출발하는 실험이다. beta를 고정하거나 학습 중 다시 초기화하지 않는다. Z의 시간 회전,
내용·위치 위상, agree까지 결합되므로 이 초기화만으로 선행 강화·후행 약화나
성능 개선을 보장하지는 않는다. 앞서 진행한 380k 변환·재개 진단은 학습된 beta를 유지한 결과다.

로컬 검증에서는 모델의 이전 구현과 출력·gradient가 일치했고, CPU 자체 검사7개 및 기존 변환 회귀 검사6개가 통과했다.
`__file__`가 없는 셀·커널 인자 조건에서 실제 실행과 재개를 확인했고,
d832 BF16 GPU 학습·저장 및 작은 모델의 BF16 `torch.compile` 학습도 실행했다.

## 구조와 근거

변경 위치는 [lt/train.py](../lt/train.py)의 `LTLayer`와 `W_C`다.
헤드별 실수행렬 크기는 그대로 `104 x 832`이며, 앞 52행과 뒤 52행을 복소 주소의
실수부와 허수부로 사용한다. 읽기와 쓰기는 같은 투영을 공유한다.

```text
v1.7:  P = transpose(QR(transpose(wc_raw)).Q)
v1.71: P = wc

A = P의 앞 52행
B = P의 뒤 52행
u = A q + i B q                 q: 현재 블록에서 입력을 재주입한 hidden
unit(u) = u / (norm(u) + eps)   헤드마다 복소 52성분 전체의 노름
```

v1.7은 QR로 `P P^T = I`를 강제한다. v1.71은 `wc` 자체가 파라미터이며,
학습 중 행의 길이와 상호 각도도 변할 수 있다. 주소 출력의 기존 정규화는 유지한다.
이는 행렬을 직교화하는 것과 다른 연산이며, 새 RMSNorm이나 별도의 Q/K 투영을 추가하지 않는다.

실수 성분 두 개를 복소수로 묶고 위상 회전을 적용하는 데 투영행렬의 직교성은 필요하지 않다.
[Mamba-3의 입력 투영 구현](https://github.com/state-spaces/mamba/blob/main/mamba_ssm/modules/mamba3.py#L100-L120)도
일반 선형투영 뒤 출력 정규화를 사용한다. 이 선례는 자유 투영의 설계 가능성을 뒷받침하며,
현재 모델에서 성능이 좋아진다는 근거는 아니다.

QR의 부호 점프는 실제로 관측됐지만, 그 부호만 복원한 비교가 관측된 성능 저하를
복구하지는 못했다. 이번 수정은 직교 제약과 파라미터화까지 함께 바꾸므로
그 비교와 구별한다. 상세 근거는 [v1.7 급락 연구](v17_collapse_research.md)에 있다.

나머지 forward는 v1.7과 같다.

```text
q = h + sqrt(d) * input_embedding
u = W_C q
z_new = rho * exp(i * omega) * z_old + sqrt(max(1-rho^2, 1e-6)) * u
a = read_kernel(unit(u), psi)
G = gain * write_kernel(unit(z_new), beta) * agree(values)
W_new = (1-eta) * W_old + eta * G
a_eff = (1-lambda) * a + lambda * W_new
y = q + value_transport(a_eff, values)
r = y + bilinear_MLP(y)
h_new = r / sqrt(1 + norm(r)^2 / d)
logits = W_cls(h_new)           세그먼트 마지막 블록의 출력에서 계산
```

`z`는 정규화 전의 `u`를 적분한다. 읽기 커널에는 현재 주소의 정규화값,
쓰기 커널에는 이력 `z`의 정규화값을 쓴다. 새 퍼즐에서는 `z=0`부터 시작하고,
`W`는 첫 `G`로 초기화한다. `agree`, 거리 감쇠, 복소 회전, post MLP, 고정 게이지도 유지한다.

## 380k 체크포인트 변환

[lt/convert_v171.py](../lt/convert_v171.py)는 v1.7의 **실효 투영**을 새 `wc`에 복사한다.
raw, 평가용 모델, EMA shadow마다 각자의 `wc_raw`를 독립적으로 QR 분해한다.
raw의 QR 결과를 EMA에 복사하면 시작 평가 함수가 달라지므로 그렇게 하지 않는다.

```bash
python -m lt.convert_v171 \
  runs/v17_recovery/checkpoints/v17_step_380000.npz \
  runs/v1_71_converted/step_380000.pt \
  --device cuda
```

원본은 변경하지 않으며 기존 출력 파일은 기본적으로 덮어쓰지 않는다.
이 실행은 원래 GPU 계산과 같은 CUDA QR로 시작 투영을 보존한다. CPU QR와 CUDA QR의
부호 선택·수치가 같다고 가정하지 않는다. 변환 backend와 원본 SHA256은 metadata에 남긴다.
그 밖의 모델 파라미터·buffer는 유지하며, 이후 직접 행렬에 적용되는 optimizer 갱신은 달라진다.

실제 변환 검증에서 복구한 원본 v1.7과 v1.71을 CUDA BF16 autocast로
8퍼즐 × 16세그먼트 실행했다. raw와 EMA 각각에서 `logits`, `h`, `W`, `z`의
최대 절대 차이가 모두 0이었고, 모든 세그먼트의 예측도 같았다.
검증 기록은 `runs/v1_71_converted/validation.json`이다. 이 검증은 시작 함수의 보존을
확인한 것이며, 갱신 이후 학습 궤적의 동일성을 뜻하지 않는다.

변환은 **가중치에서 시작하는 새 학습**이다. step 380000과 seed는 보존하지만 optimizer moment,
RNG 상태, carry, 데이터 진행 위치는 가져오지 않는다. 데이터 커서는 `iter_id=0`,
`batch_in_iter=0`이다. 원래 380k 학습의 연속 재현으로 해석하지 않는다.

## 짧은 재개 진단과 관측

변환된 380k 가중치에서 실제 갱신을 수행해 loss와 예측 변화를 확인한다.
이번 실행은 앞선 원본 QR 진단과 같은 길이인 256회 갱신으로 범위를 정한다.

```bash
python -m lt.resume_v171 \
  --checkpoint runs/v1_71_converted/step_380000.pt \
  --out runs/v1_71_probe_380k_256 \
  --steps 256 --eval-every 64 --save-every 64 \
  --eval-n 128 --final-eval-n 2048
```

[진단 스크립트](../lt/resume_v171.py)의 위 실행 조건은 다음과 같다.

| 항목 | 설정 |
|---|---|
| 학습 시작 | 변환된 v1.7 raw 380k, fresh AdamATan2 + sparse signSGD |
| 학습률 | dense와 puzzle embedding 모두 `1e-4` 상수, warmup 없음 |
| 추가 갱신 | 256회, 종료 step 380256 |
| 배치·반복 | 배치 128, 퍼즐당 16세그먼트, 세그먼트당 8블록 |
| 역전파 | 세그먼트마다 감독·갱신, `h/z/W` detach |
| 정밀도 | FP32 가중치, 기존 BF16 autocast, compile 끔 |
| 데이터 | 기존 Sudoku-Extreme 1k와 증강, seed 0, 데이터 처음부터 |
| 중간 평가 | 시작 시점과 64갱신마다 같은 held-out 128문제, fresh 16세그먼트 |
| 마지막 평가 | held-out 2048문제, fresh 16세그먼트 |
| 가중치 구분 | raw와 EMA를 각각 평가, EMA도 독립 변환된 380k에서 시작 |

`steps.jsonl`은 실제 학습 loss와 gradient norm, `eval.jsonl`은 고정 가중치 평가를 기록한다.
`exact`는 81칸이 전부 정답인 퍼즐 수다. 중간 평가는 같은 128문제를 사용하며,
한 퍼즐을 푸는 동안 파라미터를 고정한다. 학습 중 완답 수와 이 평가를 구분해 읽는다.
64갱신마다와 정상 종료 시 optimizer·EMA·carry·데이터 커서를 포함한 체크포인트를 저장하며,
최종 결과는 `complete.json`에 기록한다. 요청에 따라 평가 크기와 스텝 수를 명시해 실행한다.

이 진단은 짧은 갱신 구간의 변화와 실패 여부를 확인한다. 짧은 구간이 정상이어도
장기 학습 안정성, 과거 328k 급락의 해결, 긴 세그먼트 외삽 개선까지 보장하지 않는다.

## 실제 256회 갱신 결과

2026-09-27 실행 완료. raw 380k에서 위 조건으로 380256까지 학습했으며,
전체 학습·평가 시간은 약 342초였다. 모든 학습 loss와 gradient가 유한했다.
학습 LM loss 범위는 0.03515–0.74252, dense gradient norm 범위는 0.26646–2.90547이었다.
`wc`와 이전 `wc_raw`는 파라미터화가 다르므로 gradient norm 감소 자체를 비교 기준으로 삼지 않는다.

전체 held-out 2,048문제, 가중치 고정, fresh 16세그먼트 평가:

| 가중치 | 갱신 전 완답 | 256회 후 완답 | 셀 정확도 전 → 후 |
|---|---:|---:|---:|
| raw | 664/2048 (32.42%) | 803/2048 (39.21%) | 75.565% → 77.579% |
| EMA | 1179/2048 (57.57%) | 1145/2048 (55.91%) | 84.729% → 83.798% |

같은 데이터·초기 raw 380k·fresh optimizer·lr을 사용한 세 조건의
고정 앞 128문제 결과도 비교했다. 표의 숫자는 raw / EMA 완답 수다.

| 추가 갱신 | 기존 v1.7 QR | 부호 연속 QR | v1.71 직접 투영 |
|---:|---:|---:|---:|
| 0 | 49 / 74 | 49 / 74 | 49 / 74 |
| 64 | 38 / 75 | 35 / 77 | 42 / 73 |
| 128 | 40 / 75 | 45 / 74 | 57 / 72 |
| 192 | 40 / 72 | 48 / 72 | 44 / 69 |
| 256 | 45 / 70 | 48 / 74 | 59 / 77 |

이번 구간에서는 v1.71이 수치 발산 없이 업데이트됐고 raw 전체 완답은 139개 늘었다.

47,075의 별도 평가에서는 개별 퍼즐 궤적도 저장했다. 한 번이라도 완답한 퍼즐은 212개,
