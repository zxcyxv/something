# 2026-10-07 계획: 연속 시간 위의 인접 블록 STDP

2026-10-06 논의를 정리한 다음 실험 계획이다. 구현·실험은 아직 하지 않았다.

## 목적

지금 STDP가 보는 쌍은 같은 블록 안의 pre와 post뿐이고, 그 안의 선후는 위상이라는
학습된 latency 값이다. 반면 모델 안에서 실제로 인과가 일어나는 곳은 블록 k의 상태가
블록 k+1의 상태를 만드는 재귀다. "블록 k의 pre 발화 → 블록 k+1의 post 발화" 같은 쌍은
진짜 인과 순서인데, 지금은 이런 쌍을 전혀 보지 않는다. **이 쌍이 학습에 쓸모 있는
신호인지**가 이 구조에서 블록 간 결합을 시험하는 이유다.

누적(기억 지속)은 이 목적과 별개의 축으로 다룬다. 블록마다 G를 새로 만들고 읽은 뒤
초기화하는 지금 구조도 Fast Weight의 "매 스텝 Hebbian 쓰기와 인출" 해석으로 성립한다.

## 선행 결과: 2026-10-03 재귀 시간 KV-STDP

원래 `lt/train.py`의 KV-STDP가 블록 간 쌍을 trace로 본 모델이었다
([기록](2026-10-03/README.md)).

```text
eK_r = λ·eK_{r−1} + (1−λ)·K_r       (pre trace)
eV_r = λ·eV_{r−1} + (1−λ)·V_r       (post trace)
G_r  = mean_p[ V_r · eK_{r−1}ᵀ − eV_{r−1} · K_rᵀ ]     블록 간 LTP − LTD
M_r  = M_{r−1} + G_r                                     G 누적
```

같은 조건, 약 3,000스텝의 훈련 칸 정확도(종료 세그먼트 16개 평균):

| 구조 | 정확도 |
| --- | ---: |
| B만 (같은 블록 Hebbian, `V_r K_rᵀ`) | 94.2% |
| B + G (같은 블록 Hebbian + 블록 간 STDP, 누적 없음) | 90.6% |
| G만 (블록 간 STDP만) | 72.7% |
| M (블록 간 STDP 누적) | 54.8% |

- 블록 간 쌍만으로도 학습은 됐다.
- 같은 블록 결합보다 약했고, 더해도 이득이 없었다.
- 누적 M은 크게 나빠졌고 원인은 확정되지 않았다.

그때는 블록 안 타이밍(위상)이 없었다. 블록 간 쌍은 "한 블록 차이"라는 정수 시간만
있었다. 이번 질문은 **위상으로 블록 안 타이밍을 주고 연속 시간으로 블록 경계를 이으면,
블록 간 인과 쌍이 도움이 되는가**다.

## 설계

### 시간축

블록 k의 발화 시각을 `t = k·T + φ`로 둔다. 모든 채널이 공통 시계를 쓰므로 위상차는
연속 시간차다. φ ∈ (−π/2, π/2)라 블록 폭이 π이므로 **T = π**이면 블록들이 빈틈 없이
이어진 연속 시간이 된다. T = 2π이면 블록 사이에 π의 빈 구간이 생긴다.

### 쓰기

`W(V, φV; K, φK) = mean_n V·K·L(φV − φK)`, L은 tanh·sech(창 크기 ×2, peak 1).

```text
G_k = W(V_k,     φV_k;        K_k,     φK_k)          같은 블록 (현재와 동일)
    + W(V_k,     φV_k;        K_{k−1}, φK_{k−1} − T)  pre 이전 블록, post 현재 블록: 시차 π+δ ∈ (0, 2π), 항상 LTP
    + W(V_{k−1}, φV_{k−1} − T; K_k,    φK_k)          post 이전 블록, pre 현재 블록: 항상 LTD
read = Q_k · G_kᵀ
```

- 이전 블록 위상을 T만큼 당겨 넣으면 기존 fused 커널을 그대로 쓴다. 부호 판정·근사 없음.
  커널은 |φ|가 적당하면 되므로 φ − π 입력도 FP32 범위에서 안전하다(p ≤ e^{4π}).
- 블록 간 쌍의 세기는 블록 안 위상이 정한다. 이전 블록에서 늦게 발화한 pre와 현재
  블록에서 일찍 발화한 post는 시차가 짧아 강하게 결합한다. 10-03 모델에 없던 정보다.
- 두 블록 이상 떨어진 쌍은 시차 ≥ π라 창 값이 tanh·sech 기준 0.09 이하(×2 창에서 0.17
  이하, peak 1 대비)이므로 첫 실험에서는 자른다. 필요하면 지수 trace로 붙인다(꼬리가 지수라 곱으로 분리된다).

### 누적하지 않음

G_k는 매 블록 새로 만든다. 이전 블록의 (RoPE 적용 K, φK), (V, φV)만 한 블록 동안 보관한다.
10-03 누적 M의 실패 원인을 모르므로 목적(블록 간 인과 쌍)과 누적(기억 지속)을 분리해
앞의 것만 먼저 시험한다.

누적을 시험할 때의 형태(다음 단계):

```text
G_k = λ_c ⊙ G_{k−1} + ΔG_k,   λ_c = e^{−T/τ_c}
```

공통 시계(주파수)와 공통 창 폭 τ는 유지하고, 기억 수명 τ_c만 채널 또는 헤드별로 둔다.
시계가 하나여도 시정수는 여러 개일 수 있다. 창 폭은 위상 스케일로 이미 실효적으로
조절되므로 채널별 τ는 두지 않는다(쌍별 τ는 커널의 지수 분리도 깨뜨린다).

### 구현 메모

- 하네스(`lt/experiment_free_phase_windows.py`)의 `memory_step`에 블록 간 슬롯
  `e_k`, `e_v`가 있다. 이전 블록의 (kr, φK), (v, φV)를 담아 반환한다.
- 새 퍼즐(`fresh`)이면 0으로 초기화한다(기존 trace 처리와 같다).
- 세그먼트 경계에서는 carry로 넘기며 detach된다(trainer 기존 동작). RoPE는 저장 시점에
  적용한 kr을 보관한다.
- 커널 호출 3배. 예상 스텝 시간 약 0.29초(현재 0.19초), 3,008스텝 약 15분.
- 테스트: FP64 직접 pair 합(시간 이동 포함)과 값·gradient, fresh 초기화, carry 저장·재개,
  두 residual RMSNorm 위치.

## 시작 전에 정할 것

1. **T**: π 고정(빈틈 없는 연속 시간) 또는 헤드별 학습. 추천: 첫 실험은 π 고정.
2. **블록 간 항의 세기**: 같은 창 그대로(STDP에 충실) 또는 0 초기화 학습 gain
   (처음엔 E0과 같은 모델에서 출발해 모델이 사용 여부를 정함).
3. **GPU**: ×2 장기 런이 GPU를 쓰는 중. E1을 위해 잠시 멈출지, 동시에 돌릴지
   (동시 실행은 속도만 느려지고 학습 결과에는 영향 없음).
