## 1. 아키텍처와 하네스 연결

`lt/research_phase_clock_stdp.py`(사용자 작성). 한 블록:

```text
h ← h + √d inj;  q, k, v = heads(W h);  q̂, k̂ = L2 단위화;  qr, kr = RoPE(q̂), RoPE(k̂)
dt = softplus(W_dt h + b_dt) [B,H,T];  ω_K, ω_V = π tanh(W_f h + b_f) [B,H,T,P]
φ_r ← wrap(φ_r + dt ω_r)                              칸·헤드·쌍마다 블록 축으로 누적 (새 퍼즐이면 0)
λ_r = exp(−a_r dt),  a_r = softplus(raw) [H,P]
E_K ← λ_K E_K + (1−λ_K) k̂ e^{−iφ_K}                    (이번 블록 사건 포함, 회전 전 저장)
D_V = λ_V E_V;  E_V ← D_V + (1−λ_V) v e^{+iφ_V}
S = Σ_n [(v e^{iφ_V})ᵀ RoPE(E_K) + D_Vᵀ (kr e^{−iφ_K})]
G = Σ_n v krᵀ + α_h Im S;   read = qr Gᵀ
h ← RMS(h + W_o read);  h ← RMS(h + SwiGLU(h))
```

모든 (post, pre) 사건 쌍이 정확히 한 번, 가중치 `(1−λ_earlier)·exp(−a Σdt)·e^{i(φ_post − φ_pre)}`로 들어간다.
창은 명시적 함수가 아니라 흔적 재귀에서 나온다: 위상 창 `sin Δ`(R = 1) × 경과 시간의 지수 감쇠 × 각 뉴런 시계의 시차.
초기화는 W_dt = W_f = b_f = 0이라 φ = 0, Im S = 0으로 B-only와 같고, α = 1이라 주파수 헤드에만 기울기가 들어간다.
dt·λ·α의 기울기는 위상이 0에서 벗어난 뒤 생긴다. carry: `coupling = cat(φ_K, φ_V)`, `key_trace = cat(Re E_K, Im E_K)`,
`value_trace = cat(Re E_V, Im E_V)`(세그먼트 경계에서 detach). 파라미터 9,241,467(기준 8,540,915).

- 참조하는 하네스 심볼(`ExponentialPhaseCurrentReadInner`, `inv_softplus`, `_is_no_decay`, carry 슬롯,
  `configs/free_phase_window_research.json`)이 모두 있어 수정 없이 들어갔다.
- `--selftest` 6/6 (CPU FP64): 흔적 재귀 = 모든 사건 쌍의 명시적 합(중간 reset 포함, 1e-11), 초기화에서 위상 0·α = 0과 동일,
  3+3 세그먼트 = 6블록 unroll, 레인별 reset, 초기 기울기는 주파수 헤드에만, 모든 clock 파라미터의 유한 기울기.
- GPU preflight 12스텝(torch 경로, checkpoint 켬): 141.4 ms/step, peak 3.8 GiB. 스텝 0에서 `clock_freq`만 기울기 ≠ 0,
  11스텝째 dt·decay·α 모두 기울기 생성 ([preflight/](2026-10-13/preflight/)).
- torch 경로로 시작한 런(`phaseclock_l0.1_a1_dt1_swiglu_20261013`)은 2,525스텝에서 멈추고(사용자 결정: 융합 커널 먼저)
  로그만 보관했다. 1,953 평가 53.2% / 0.

### 1.1 torch 경로가 느린 이유

연산 수로 추정한 블록당 비용: GEMM 6개는 작고, `[B,H,T,D]`(8.6M 원소 FP32) 원소별 연산 약 40개가 메모리 트래픽
(각 70 MB 왕복)으로 블록당 ≈ 3 ms. 8블록 × (forward + checkpoint 재계산 + backward) ≈ 90 ms가 메모리 경로 비용이고
나머지 ~50 ms는 기준과 같은 사영·FFN·norm이다. 기준의 torch 경로도 104.5 ms(R = 2)·64.7 ms(trace)였으므로
공정한 비교는 1.4~2배다.

## 2. 융합 Triton 커널 (`lt/phase_clock_fused.py`)

### 2.1 설계

한 블록의 메모리 경로 전부를 커널 안에서 처리한다: K L2·RoPE, 위상 태그 cos/sin, 흔적 갱신 E_K'·E_V'의 계산과 저장,
Hebb + Im S 4항의 특징 GEMM 누적, read. 토치에는 `[B,H,T,P]` 크기의 위상 누적·λ·fresh 레인 reset만 남는다.
RoPE가 쌍별 스칼라와 교환하므로 `RoPE(E_K') = λ_K RoPE(E_K) + (1−λ_K) kr e^{−iφ_K}`를 레지스터에서 만들고 저장은 회전 전 흔적이다.

- forward: (batch, head)당 한 프로그램이 두 채널 패리티의 누적기 4개를 들고 모든 피연산자를 한 번만 읽는다
  (처음 버전은 패리티별 두 프로그램이 입력을 두 번 읽어 1.47 ms/블록, 합친 뒤 1.10 ms).
- backward 4개: dG·dq는 `pairangle_fused`와 공유. V쪽(dv, dE_V, dφ_V, dλ_V, dα)과 K쪽(dk, dE_K, dφ_K, dλ_K, dθ).
  다음 블록에서 오는 흔적 기울기 dE_K', dE_V'도 입력. V·K를 한 커널로 합치는 시도는 dG 블록의 레지스터 전치(`tl.trans`)에
  공유 메모리 128 KB가 필요해 4090 한도(99 KB)를 넘어 버렸다.
- 타일 BT = 16, BP = 64, warps 8(warps 4보다 spill 232 → 42). BT = 32는 spill이 커져 2~3배 느리다.
- 불투명 custom op `lt::phase_clock_attention`(출력 read, G(기울기 없음), E_K', E_V'). BF16 dot 피연산자, FP32 누적·흔적·위상.

### 2.2 검증 (`lt/test_phase_clock_fused.py`, 4개 통과)

- FP64 참조(`reference_phase_clock`) 대비 출력 4개와 입력 11개(q, k, v, E_K, E_V, φ_K, φ_V, λ_K, λ_V, θ, α) 전부의 기울기:
  FP32 dot 3e-6, BF16 dot 2e-2 이내. 상류 흔적 기울기가 있는 경우와 없는 경우 모두.
- BF16 사영 입력과 λ ∈ {0, 1} 경계. compile = eager.
- 연구 모델의 torch 경로와 triton 경로가 `memory_step` 출력과 기울기(clock 파라미터 포함)에서 일치(1e-4).

- 타이밍 항의 비중은 17% → 8%로 줄고 α는 7개 헤드에서 0.2 이하가 됐다(헤드 0만 0.8). "α 감소는 |Im S| 증가의 스케일 보정"이라는
  가설은 이 비율로 기각된다. 모델은 홀수 창을 거의 쓰지 않는 쪽으로 간다.
- ω ≠ 0 자체는 문제가 아니다. 이 설계에서 k블록 전 사건과의 시차는 `Δ + k·ω`이고, 블록 축을 시간으로 만드는 것이 ω다.
  10-12 §14(같은 블록 안의 V–K 상대 위상에 오프셋을 계속 더함)와는 다른 구조다. 상대 위상 `φ_V,A(b) − φ_K,B(b−k)`의
  일관성은 재지 않았다.
- α×0 추론 절제는 하류가 그 항을 포함한 G에 맞춰져 있어 스케일 절제가 되므로 하지 않았다. 정보만 없애는 절제는
  칸 간 위상 섞기(10-10 §6)나 시계 정지(ω×0)인데, 사용자 결정으로 보류했다.

## 6. 문헌 재확인: 전이 시점과 lr·wd

- Lewkowycz, Gur-Ari 2020 (NeurIPS, arXiv 2006.08643) [원문 PDF]: "The number of SGD steps until a model achieves maximum
  performance is t* ≈ c/λ, where c is a coefficient that depends on the data, the architecture, and all other hyperparameters";
  vanilla SGD에서 t* ≈ c′/(η·λ). 기제는 스케일 불변(BN) 동차 망에서 L2가 유효 학습률 `η e^{2ηλt}`를 키우는 것.
- Pracher 등 2026 (arXiv 2609.26679) [원문 HTML]: "the grokking timescale is controlled by the product of learning rate and weight decay".
  전배치 SGD, 결합 L2, modular addition MLP와 d_model 32 1블록 transformer. transformer 코호트의 held-out 80% 교차 중앙값 η·λ·s₈₀ ≈ 0.92.
  단서: "(ηλ_W)⁻¹-type timing alone does not distinguish feature learning from fixed-feature dynamics". 기제는 노름 감쇠가 아니라 residual–NTK 되먹임.
- 우리 두 런은 AdamATan2 + 분리형 decay(`p ← p(1−ηλ)`), η = 1e-4, λ = 1.0으로 ηλ = 1e-4가 같다. 법칙대로면 전이 시점이 같아야 하는데
  기준 ~19.5k(ηλs ≈ 2.0), phase-clock ~31k(ηλs ≈ 3.1)다. 둘 다 Pracher의 0.92와 같은 자릿수이지만 법칙은 두 런을 구분하지 못하고
  차이는 "c가 아키텍처에 의존한다"는 자리에 들어간다. 기준의 전이는 학습 loss와 held-out이 함께 움직이므로(§3.2) 엄밀한 grokking
  (학습 loss 바닥 뒤의 늦은 일반화)이 아니라 최적화의 전이다.

## 7. 해석

- 기준 모델의 "STDP" 창 `sin(φ_V − φ_K)`는 위상이 쌍 자신의 각도라서 시간 규칙이 아니라 **내용 게이트**였다(10-12 §4: 가소성에는 시각,
  망에는 내용 좌표). 이 런의 위상은 적분된 시계 상태라 고정점에서도 계속 돌고, 현재 내용의 함수가 될 수 없다. 즉 이 모델은
  "기준 + 역사"가 아니라 **"기준의 즉시 내용 창을 빼고 역사 창을 넣은 것"**이다. STDP의 정의(잠재 시간, 경과 시간 감쇠, 블록을 넘는
  pre/post 순서, 쌍마다 한 번)에는 훨씬 가깝고, 그 대가로 내용 게이트를 잃었다.
- 그 결과와 맞는 관측: 전이 지연, 약한 배치 내 적응, 타이밍 항 비중 감소와 α 감소, 그러면서도 같은 loss에서 같거나 조금 높은 held-out과
  같은 범위의 외삽.
- α에 대한 사용자 질문(헤드당 스칼라가 필요한가, 스케일 관리로 더 나은 형태): α는 Hebb/타이밍 비율을 정하는 최소 장치일 뿐이다.
  대안은 (1) 흔적 입력 게인 g_K, g_V [H,P]로 옮기기(α 삭제), (2) Scarpetta식 복소 이득 `Re[e^{−iψ} S]`(원리적이지만 Re S가 과거
  운반자를 포함해 10-12 §10의 J 읽기 결론과 충돌), (3) 상태 의존 게이트 α_n = σ(W h)(v1.8 선택적 가소성과 같은 자리).
  V 흔적이 원시 |v|를 쌓아 Im S의 크기를 정하므로, 스케일 문제라면 V 흔적을 타이밍만 들게 하는 쪽이 더 깔끔하다.
  §4의 측정으로는 스케일 문제가 아니었다.

## 11. 이론 명세 검토와 문제의식의 재서술

사용자의 설계 명세(Phase-Clock STDP 이론 명세서, 2026-10-13)를 읽었다. 요지: Hebbian과 STDP의 차이는 복소 학습률의 위상 하나이므로(P1)
Δ = 0을 정하는 공통 영점(P2 게이지 보조정리, P3 공통 시계)과 실제 시간(P4 주기화 = 정상성, P5)이 있어야 "STDP"가 함수적 내용을 갖는다.
pairangle의 쌍 각도 위상은 게이지(결함 1)라 거부하고, 전용 head의 블록 축 누적(D1)과 공통 Δ(D2)를 택했다.

오늘 결과를 명세의 언어로 놓으면:
- 명세 8.7의 열린 문제 "ω를 공통 성분 + 뉴런별 편차로 나누지 않았다"가 1런에서 그대로 터졌다. R3이 보장하는 것은 절대 영점뿐이고 창이 쓰는 상대 잠복기는 묶이지 않았다.
- 더 근본적으로, 두 런의 위상은 **뉴런의 속성이 아니라 h의 별도 사영**이다. k̂·e^{−iφ_K}에서 k̂는 뉴런, φ_K는 다른 데서 온 꼬리표다.
  명세 G3("비대칭의 방향은 관찰된 발화 순서에서 와야지 사영의 기하가 정하면 안 된다")를 전용 head가 그대로 위반한다.
  8.5가 허용한 "같은 블록 안의 순서는 학습된 증분이 정한다"가 그 틈이다. 자유 head는 내용과 결별하면 잡음(1런), 묶이면 배치 적합 채널(2런)이다.
- Mamba-3에서 가져온 것은 복소 상태 재귀(흔적 = 태그 형태의 복소 SSM)와 RoPE 트릭(P6)이며 이 부분은 옳다. Mamba-3의 위상은
  같은 채널의 경과 시간만 뜻하고 채널 사이의 잠복기 개념이 없다. 상대 잠복기는 우리가 얹은 것이고 그것이 깨졌다.
- 명세의 "α는 필요한가" 질문에 대한 측정 답: 스케일 보정이 아니었다(§4·§9).

재서술한 요구 조건: 타이밍 태그는 (1) 영점이 고정되고 보상 불가능해야 하고, (2) 재귀 궤적에서 **관측**되는 양이어야 하며,
(3) 상대 잠복기가 내용에 묶이고 유계여야 하고, (4) 그것을 만들기 위한 **추가 파라미터가 없어야** 한다. 두 런은 (2)·(4)를 위반했다.
명세가 D1에서 버린 대안 중 "쌍의 atan2"는 뉴런의 속성이라는 점에서 옳았고 게이지(상수 회전)만 문제였다 —
각도 자체가 아니라 **각도의 블록 간 변위**를 쓰면 상수 회전이 상쇄된다. 이것이 3런이다.
(명세의 사소한 불일치: 8.7의 "16세그먼트 × 16블록 = 256블록"은 실제 8블록이라 128블록; 10절의 "Triton 경로 없음"과 9.1의 "selftest 미실행"은 오늘 작업으로 바뀜.)

| λ | 0.10 | 0.10 |

| 블록별 변위 (블록 2 / 4 / 8 / 128) | 0.85 / 0.25~0.39 / 0.12~0.19 / 0.09~0.13 rad | 1.0 / 0.24~0.38 / 0.11~0.17 / 0.07~0.11 rad |

- α가 꺼지지 않고 오른다(10-09 α=1 런과 같은 모양). 타이밍 항이 Hebb와 같은 크기다.
- 배치 암기가 없다(종료 완답 36%). 파라미터가 없으니 악용할 채널이 없다.
- 위상이 정착한다: 블록 2에서 1 rad 움직인 뒤 블록 8 이후 0.1 rad 안팎, 쌍의 70%는 멈춘다. 상대 위상 분포(std 1.7)는 블록 8 이후 고정된 내용 의존 패턴이다.
- λ = 0.10 그대로라 역사는 직전 1블록 정도만 본다. 사실상 "게이지 없는 pairangle"로 작동 중이다.
- 학습 loss: 기준보다 0.02 높은 채 같은 속도. 기준의 이륙(17~18k, 1k당 감소 0.005 → 0.010~0.015, 23~25k 0.024~0.031)은 31k까지 없었다(평균 0.004/1k).
- 27.3k·29.3k의 EMA 급락(428 → 278 → 276)은 raw가 아니라 EMA 쪽 흔들림이었다: raw는 새 carry 512문제에서 73 → 75로 제자리였고(EMA 134 → 81),
  학습 퍼즐 ≈ held-out이라 데이터셋 암기는 아니다. raw가 EMA보다 훨씬 나쁜 상태(19.5k 38 대 113)가 이 계열의 공통점이고, 학습 중 종료 완답
  45%와 raw 새-carry 15%의 격차는 leaky와 같은 종류의 배치 내 가중치 적응이다(파라미터 없는 시계에서도 생기므로 통로는 타이밍 항 자체로 보인다 — 가설).
- **이륙은 33k에 왔다**: 31.2k 416 → 33.2k 555 → 35.2k 627 → 37.1k 579 (integrate와 같은 ~12k 지연). 세션 종료 시점 37.1k, 런은 50.8k까지 계속 돈다.
