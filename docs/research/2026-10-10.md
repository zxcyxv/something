## 2. 쌍선형 FFN 재검토와 SwiGLU 전환

원 저장소 `zxcyxv/LinearTuring`의 근거:
- 8/24 `sudoku_runs/2026-08-24/REPORT.md`: 선형 경계 3형식이 모두 0.66~0.68 벽. 토큰 내 채널곱이 필수.
- 8/26 `sudoku_runs/2026-08-26/REPORT.md` §7: 쌍선형 경계 `h + W_d[(W_g h)/2 ⊙ W_u h]`가 SwiGLU와 같은 곡선(76k 0.800 / 835).
  §7.5: Φ 포화가 ‖h‖ ≈ 3.4(원소 std 0.11)를 고정해 g std 0.23~0.31이므로 SiLU가 다항식 구간. "URM은 RMSNorm이
  MLP 입력을 원소 O(1)로 고정 → 포화 가능성 높음(미측정)".

측정(`scripts/probe_swiglu_linearity.py`, `scripts/probe_bilinear_vs_swiglu_alpha1.py`):

| | FFN 입력 원소 RMS | g std | P(\|g\| > 1) | `SiLU(g)u` 대 `g u / 2` 상대 차이 |
| --- | ---: | ---: | ---: | ---: |
| URM 1-layer 10k (EMA) | ~1 | ~1.0 | 0.42 | 출력 0.40 |
| α = 1 초기화 (두 residual RMSNorm) | 1.00 | 0.58 | 0.08 | 중간 활성 0.45 |

학습된 URM에서 SiLU를 g/2로 바꾸면 512문제 70.9% / 94 → 11.1% / 0. 쌍선형 = SwiGLU라는 등가는 Φ 체제에서만 성립했다.
"활성화 함수 없는 재귀 모델"은 STDP로 방향을 바꾼 뒤 목표가 아니므로, 이후 FFN은 SwiGLU를 쓴다
(`--boundary-ffn swiglu`; 게이트만 g/2 → SiLU(g), 같은 가중치 초기값). 쌍선형 가중치 텐서 분해 해석은 선택지로 남긴다.

## 3. 정밀도 기록과 BF16 GEMM

기록 조사 결과 memory 경로의 FP32는 설계 선언(`lt/train.py:20`)뿐이고 측정 근거가 없다. 근거가 있는 것은 v1.8 게이트
(`docs/v18.md:135`, BF16에서 1 − A 해상도 ≈ 0.004)로 지금 구조(누적 없음)에는 해당하지 않는다. TF32 꺼짐은 URM
`pretrain.py`에 맞춘 것이고(원 저장소 `kaggle/예외사항.md`), 이 shape에서 TF32는 속도 이득이 없었다.

`--feature-precision bfloat16`을 pairangle 경로에 적용(Hebbian·타이밍·읽기 GEMM 피연산자 BF16, 정규화·위상 FP32).
같은 가중치(3,475스텝)에서 FP32 대비 loss 0.859737 / 0.859752, gradient 상대 L2 1.46%(cosine 0.99989),
128블록 평가 512문제 64.44% / 30 대 64.50% / 30. 스텝 시간 104 → 92 ms.

## 4. 융합 Triton 커널 (`lt/pairangle_fused.py`)

한 (batch, head)의 L2 정규화, 학습된 2D RoPE, 위상 특성, 쓰기, 읽기를 커널 하나로, backward를 커널 4개(dG, q, v, k)로 계산한다.
위상의 cos/sin은 채널 쌍에서 대수적으로(cos φ = x/ρ, 고조파는 배각 점화식) 구하고, `G = Σ_m A_mᵀ B_m`을 채널 패리티
블록으로 tensor-core dot에 누적한다. 특성 텐서를 메모리에 쓰지 않는다. G는 다음 블록에서 쓰이지 않으므로 gradient 없이 반환한다.
`--kernel triton`(기본 `torch`), 학습 엔트리에 `--no-activation-checkpoint`, `--no-boundary-save` 추가.

검증(`lt/test_pairangle_fused.py`, 3개 + 기존 19개 통과):
- FP64 atan2 참조 대비 FP32 모드 read, G, dq, dk, dv, d각도, dα 상대오차 ≤ 3e-7 (rotated/unrotated, Hebbian 유무). BF16 모드 약 3e-3.
- 모델 전체 FP32에서 torch 경로 대비 gradient 상대 L2 1.2e-6. compile = eager.

학습 1스텝 GPU 시간(batch 128, compile; `scripts/time_fused_model.py`, `scripts/profile_step.py`):

| 설정 | 시간 | 메모리 peak |
| --- | ---: | ---: |
| FP32 torch, checkpoint 켬 (이전 기본) | 104.5 ms | 4.4 GiB |
| BF16 torch, checkpoint 켬 | 91.8 ms | 3.2 GiB |
| BF16 Triton, checkpoint 켬 | 68.4 ms | 1.2 GiB |
| **BF16 Triton, checkpoint 끔** | **52.4 ms** | 3.2 GiB |
| URM 1-layer, checkpoint 켬 / 끔 | 50.6 / 38.9 ms | 0.9 / 2.7 GiB |

개발 중 고친 문제:
- 레지스터 spill(64×64 FP32 누적기 4개): forward를 행 패리티로 분할하고 피연산자를 전치된 채로 로드. forward 19 → 0.46 ms.
- qkv chunk처럼 틈이 있는 뷰 입력에서 gradient 버퍼 stride가 달라 잘못된 메모리 접근: 출력별 stride 전달.
- 커널 출력으로 텐서의 슬라이스·전치 뷰를 넘기면 inductor의 뷰 쓰기 처리에서 잘못된 접근: 출력은 모두 독립 텐서.
- `triton_op`로 등록하면 inductor가 커널을 다시 컴파일해 3~5배 느림: 불투명 `custom_op`로 등록해 Triton JIT가 실행.
- 테스트 중 stale inductor FX 캐시가 수정 전 시그니처를 호출. 학습 하네스의 `inductor_no_persist`는 이를 막는다.

L4(Ada, sm_89)는 4090과 같은 세대라 같은 설정이 맞을 것으로 보지만 실측하지 않았다. T4(sm_75)는 BF16 tensor core가 없다.
새 환경에서는 `python -m unittest lt.test_pairangle_fused`를 먼저 돌리고, 실패하면 `--kernel torch`를 쓴다.

## 6. 과적합 재측정

학습 중 기록되는 종료 세그먼트 지표(raw, train.jsonl)는 같은 배치로 세그먼트마다 15번 갱신된 뒤의 값이다. 이 지표로 비교하면
11.7k에서 학습 − held-out 격차가 α = 1 SwiGLU 20.4%p, 쌍선형 14.4%p, URM 2.5%p였다. 같은 조건(EMA, 새 carry, 16세그먼트,
각 1,000문제; `lt/probe_stdp_memorization.py`, `scripts/urm_train_vs_heldout.py`)으로 다시 쟀다.

| | 학습 퍼즐 완답 | held-out 완답 | 격차 |
| --- | ---: | ---: | ---: |
| α = 1 SwiGLU 20k | 194 (72.2%) | 182 (71.5%) | +1.2%p |
| URM 20k | 219 (72.5%) | 206 (72.2%) | +1.3%p |
| α = 1 SwiGLU 50k | 647 (87.2%) | 483 (80.9%) | +16.4%p |
| URM 50k | 527 (83.9%) | 438 (79.8%) | +8.9%p |

- 학습 중 지표의 큰 격차는 배치 내 적응이 섞인 값이었다. 20k에서는 두 모델 모두 데이터셋 수준 격차가 없다.
- 50k에서는 격차가 생기고 α = 1이 URM보다 크다. held-out도 α = 1이 높다.
- 학습 중 지표로 비교하면 B-only + QK L2 + 합산(10-08)의 19.5k 격차는 6.5%p로 URM 9.2%p, 원본 B-only(QK 정규화 없음, ÷81) 28.2%p였다.
  같은 왜곡이 있으므로 EMA 동일 조건으로 다시 재야 한다.

STDP 항 절제(같은 가중치에서 추론 시만 변경):

## 9. R = 1, 8블록: R과 반복수의 분리

`pairangle_r1_dca1_swiglu_bf16fused_20261010`. 5절 런에서 `--modes 1`만 바꿨다. 19.9 it/s. 50,850에서 중단(계획대로 50k까지).

| step | R = 1, 8블록 | R = 2, 8블록 (5절) | R = 1, 24 + 8 (8절) |
| ---: | ---: | ---: | ---: |
| 9,765 | 68.5% / 345 | 67.3% / 274 | — |
| 17,577 | 68.0% / 63 | 68.6% / 162 | 70.0% / 329 |
| 21,483 | 74.4% / 515 | 73.0% / 465 | 71.6% / 417 |
| 31,248 | 80.7% / 939 | 79.7% / 884 | 77.9% / 832 |
| 41,013 | 83.1% / 1,075 | 82.6% / 1,064 | 80.8% / 962 |
| 48,825 | 84.0% / 1,101 | 83.5% / 1,112 | 81.9% / 1,007 |
| 50,778 | 84.2% / 1,139 | 83.0% / 1,074 | 82.2% / 1,024 |

- 8블록에서 R = 1과 R = 2는 같은 수준이다(50k까지). 8절의 하락은 R이 아니라 세그먼트 앞의 no-grad 24블록에서 온 것으로 본다.
- 두 8블록 런 모두 11~18k에 완답이 급락했다가(R = 1 최저 63, R = 2 최저 162) 20k 이후 회복했다. 24 + 8 런에는 이 급락이 없었다.
- 이후 실험은 R = 1을 쓴다.

가설(미검증): 성능을 정하는 것은 총 반복 수가 아니라 gradient가 거치는 반복의 길이다. no-grad 구간은 수렴한 상태 뒤의 블록만
학습하게 만든다. TRM(Jolicoeur-Martineau 2025)은 재귀 전체를 역전파해 1-step gradient 근사보다 Sudoku-Extreme 성능이 크게
올랐다고 보고했다(수치는 원문 확인 필요). 검증: R = 1에서 (A) no-grad 0 + grad 16, (B) no-grad 8 + grad 8을 8블록 기준과 비교.
A가 B보다 높으면 gradient 범위가 핵심이다. held-out 천장, 학습 퍼즐 미해결 비율, 외삽 오차 감소율을 함께 본다.

## 10. 이론 정리 (대화 기록)

- `1 + αW`는 STDP 창의 Kempter 분해(직류 = 발화율 Hebbian, 홀함수 = 타이밍)를 주기화하고 R개 고조파로 자른 형태다.
- 현재 쓰기는 각 칸의 현재 상태만의 함수라 정보상 상태 기반 쓰기 게이트에 포함되지만, 칸별 이득 행렬의 랭크가 1 + 2R이어서
  스칼라·대각 게이트(DeltaNet·Mamba·GLA식)로는 표현되지 않는다. 블록 사이 누적이 들어오면 현재 상태만으로 재현할 수 없는 항이 생긴다.
- R = 1에서 sin(φV − φK)는 두 단위 쌍벡터의 외적이다. 원 위의 홀함수 창 중 가장 낮은 차수다.
