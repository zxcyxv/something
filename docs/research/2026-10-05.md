## 후속: 퍼즐 상태 의존 지수형 위상

사용자 요청에 따라 새 구현과 CPU 검증 18개를 완료한 뒤, 기존 고정 위상 런을
18,300스텝에서 SIGTERM으로 정상 종료했다. 마지막 체크포인트를 CPU에서 다시
읽어 저장을 확인했다. 기존 런의 최근 체크포인트 3개는 보존했다.

새 후보는 `phase_puzzle_exp_current_only`이며,
`runs/kv_phase_puzzle_exp_fresh_20261005`에서 처음부터 학습한다.
설정은 `configs/kv_phase_puzzle_exp_full_research.json`이다.
전체 epoch 일정, no-grad 비활성화, 1,000스텝 저장, 최근 3개 보존을 유지한다.

```text
x = hidden + sqrt(hidden_size) * input_injection
c = RMSNorm(mean_tokens(x))
phiK = (pi/2) * tanh(thetaK + W_phaseK c)
phiV = (pi/2) * tanh(thetaV + W_phaseV c)
delta[b,h,i,j] = phiV[b,h,i] - phiK[b,h,j]
L = sign(delta) * exp(-abs(delta)/tau), tau=1 rad
G = (V.T @ RoPE(K) / tokens) * L
read = RoPE(Q) @ G.T
u = RMSNorm(x + W_output read)
next_hidden = RMSNorm(u + bilinear_FFN(u))
```

위상은 퍼즐·헤드·채널별이며 토큰에 걸쳐 공유하고, 재귀 블록마다 다시 계산한다.
따라서 지수창을 KV의 토큰 평균 뒤에 적용해도 정확히 같다. 위상 요약과 사영은
FP32이고, summary RMSNorm은 두 residual RMSNorm과 별개다. 모두 eps=1e-5,
학습 가능한 scale/bias가 없다. 시차는 발화 지연 위상의 차이며 wrap하지 않는다.

두 위상 사영은 zero initialization, bias 없음, weight decay=1이다. 기존 theta
초기화와 theta의 decay=0 정책을 유지해 초기 forward가 고정 위상 모델과 일치한다.
추가 파라미터는 1,384,448개, 전체는 9,925,355개다. 현재 G만 읽으며 history와
trace는 사용하지 않는다. 평균 요약으로 토큰별 독립 위상을 표현하는 것은 아니다.

검증: `python -m unittest lt.test_phase_puzzle_exp_current lt.test_phase_exp_current lt.test_unit_phase_current -v`.
직접 pair 계산과 gradient 비교, 초기 baseline 일치, zero-init 사영의 gradient,
퍼즐별 분리, FP32 phase 경로, 두 residual RMSNorm의 실제 위치와 수식,
activation checkpoint 재계산, optimizer/EMA/carry 저장·재개 및 3개 보존을 확인했다.
결과는 `docs/research/2026-10-05/puzzle_phase_tests.log`에 보관했다.

RTX 4090에서 BF16 AMP, compiled forward/backward와 optimizer가 실제로 진행됨을
확인했다. K/V phase 사영과 theta offset 네 파라미터의 gradient가 모두 finite하고
0이 아니며, zero-init phase 가중치가 갱신됐다. 시작 검증 스냅샷은
`docs/research/2026-10-05/puzzle_phase_startup_verification.json`에 보관했다.

## 후속 진단: 지수함수와 부호 경계의 구분

고정된 A와 0이 아닌 tau에 대해 `A * exp(delta/tau)` 자체는 연속이고 미분 가능하다.
현재 구현의 `sign(delta) * exp(-abs(delta)/tau)`는 별개의 양쪽 부호 창이다.
불연속은 0의 좌우 극한이 -1과 +1인 부호 접합에서 발생한다. `exp(-abs(delta)/tau)`만
보면 연속이며, abs 때문에 0에서 꺾일 뿐 값이 뛰지는 않는다. 고정 위상 실험에도
같은 부호 창이 있었으므로 지수함수 자체의 문제나 동적 모델만의 수식 오류로
설명해서는 안 된다.

기울기를 측정하기 전에 세 가설을
[protocol.json](2026-10-05/phase_gradient_audit/protocol.json)에 기록했다.
부호 경계를 넘는 유한 업데이트, 상태에서 위상으로 돌아오는 gradient 경로,
고정 가중치에서 상태 변화가 위상 순서를 바꾸는 현상을 분리해 검사했다.
실행 중인 학습의 가중치와 설정은 변경하지 않았다.

20,000스텝 체크포인트의 CPU 분석은
[results.json](2026-10-05/phase_gradient_audit/results.json)에 있다.
동일한 saved carry에서 8블록을 전개하고 셀 예측 손실을 측정했다.
FP32 분석 블록은 실제 블록과 오차 0으로 일치했다. FP64 미분 검사는 같은
수식에서 residual norm까지 FP64로 계산한 복제이며, BF16 궤적의 재현은 아니다.

- 0 경계를 넘지 않는 충분히 작은 업데이트에서는 유한차분과 gradient가 일치했다.
  자동미분의 지수 부분 미분이 잘못된 것은 아니다.
- 위상 사영만 음의 gradient 방향으로 움직인 한 측정에서 예측 손실 변화는
  -0.007463, 실제는 +0.004814였다. 각 블록의 원래 부호 마스크를 재사용한
  대조군은 -0.005276이었다. 같은 출발 함수에서 부호 전환의 영향을 분리한
  진단이며, 부호를 고정해 재학습하면 성능이 개선된다는 검증은 아니다.
- summary의 역전파만 detach하면 forward는 오차 0으로 같았다. 전체 경로의
  phase gradient norm은 1.787, detach한 경로는 0.702로 약 2.55배 차이였다.
  반면 시작 hidden의 gradient 차이는 약 1.21배였고, 인접 블록의 phase
  gradient cosine은 모두 양수였다. 심한 gradient 폭주나 시간축 상쇄 가설은
  이 표본에서 지지되지 않았다.
- 가중치를 전혀 갱신하지 않아도 부호가 바뀌었다. 블록마다 hidden이 변하고,
  그 평균 요약을 독립 K/V 사영이 서로 다른 위상으로 보내면서 채널 쌍의 순서가
  바뀌는 구조다. summary 고정 시 반전은 0이었다. attention을 제거해도
  반전이 남아 FFN 등 나머지 상태 변화만으로도 발생할 수 있었다. 요약의
  큰 정규화 증폭이나 뚜렷한 2주기 진동은 관찰하지 못했다.

22,000스텝의 서로 겹치지 않는 세 퍼즐 쌍에서 CPU FP64와 실제 CUDA BF16
블록으로 재검증했다. 결과는
[replication.json](2026-10-05/phase_gradient_audit/replication.json)에 있다.
BF16은 eager production block 경로이며 compiled 실행과의 비트 일치 검사는 아니다.
Adam 방향은 저장된 모멘트와 작은 표본의 새 gradient로 계산한 가상 phase-only
업데이트다. 전체 모델/전체 학습 배치의 실제 다음 optimizer step을 뜻하지 않는다.

| BF16 진단 방향 | 측정 수 | 실제 창에서 손실 증가 | 원래 부호 재사용 시 손실 증가 |
| --- | ---: | ---: | ---: |
| 음의 gradient, Adam 방향과 같은 파라미터 이동 크기 | 6 | 3 | 0 |
| 저장된 모멘트를 사용한 AdamATan2 방향 | 6 | 2 | 0 |

각 행은 세 퍼즐 쌍과 두 이동 크기의 조합으로 독립 학습 실험 6회가 아니다.
모든 방향의 국소 gradient 예측은 손실 감소였고, 반전 때문에 언제나 손실이
나빠지는 것은 아니었다. FP64에서도 12회 중 6회는 실제 손실이 증가했고,
원래 부호를 재사용한 12회는 모두 감소했다. 경계 전환이 국소 gradient의
예측을 깨는 현상이 여러 표본과 정밀도에서 재현됐다는 근거다.

초기 간이 점검의 10,000스텝/4퍼즐에서는 약 44–49%가 반전됐지만,
20,000스텝/8퍼즐/16블록 평균은 8.26%, 22,000스텝/6퍼즐에서는 2.68%였다.
서로 다른 체크포인트와 표본이므로 일관된 시계열 비교가 아니며,
항상 약 절반이 뒤집힌다고 일반화할 수 없다. FFN 제거의 영향도 체크포인트에
따라 달라 FFN 하나를 유일한 원인으로 지목하지 않는다. 현재 확인한 것은
상태 의존 위상과 불연속 부호 경계가 학습을 방해할 수 있는 실제 경로이며,
전체 성능 저하의 유일한 원인까지 입증한 것은 아니다.

원래 results.json의 frozen_first_sign 대조군에서 sign_flip_fraction 및
g_energy_on_L_flips는 적용 마스크가 아닌 자연 위상 순서 기준이었다. 해당
파일에 해석 정정을 추가했고, 스크립트는 두 수치를 구분하도록 수정했다.
replication.json에서는 적용된 부호의 반전율이 정확히 0임을 확인했다.
분석용 임시 체크포인트 hardlink는 분석 후 삭제했다.

## 후속 실험: 채널 어텐션으로 K/V 위상 생성

사용자 요청에 따라 `phase_channel_exp_current_only`를 구현하고 검증한 뒤
기존 평균 요약 런을 80,050스텝에서 SIGTERM으로 정상 종료했다. 마지막 체크포인트를
CPU로 다시 읽어 확인했으며, 기존 런에는 79,000 / 80,000 / 80,050의 최근 3개를
보관했다. 구현과 GPU 사전 검증이 끝날 때까지 기존 학습을 계속 실행했다.

새 실행은 `runs/kv_phase_channel_exp_fresh_20261005`, 시작 PID는 6169이며,
UTC 2026-10-05 04:11에 `NEW RUN step=0`으로 시작했다. 설정은
`configs/kv_phase_channel_exp_full_research.json`이다. 별도 스텝/시간 제한 없이
50,000 epoch의 실제 390,600 optimizer steps를 실행하며, 1,000스텝마다 저장하고
최근 체크포인트 3개를 유지한다. no-grad는 없고 별도 milestone 저장은 비활성화했다.

헤드별로 RoPE(K)와 V의 채널을 이어 붙여 208개의 채널 토큰을 만든다. 각 채널
토큰의 입력은 순서가 보존된 81칸의 활성 패턴이다. 공유 Linear(81,16)와 학습 가능한
헤드·역할·채널 embedding으로 인코딩한 뒤, K/V 채널 전체가 함께 self-attention한다.
퍼즐 또는 헤드를 가로지르는 attention은 없으며, token 평균으로 먼저 압축하지 않는다.

```text
Z = concat(RoPE(K).T, V.T)                 # [batch, heads, 2*head_dim, 81]
e = Linear_81_to_16(Z) + channel_embedding
a = softmax(Q_phase(e) @ K_phase(e).T / sqrt(16)) @ V_phase(e)
u = RMSNorm(e + output_projection(a))
y = RMSNorm(u + down(GELU(up(u))))         # phase FFN: 16 -> 64 -> 16
delta_raw_K, delta_raw_V = split_KV(readout(y))
phi_role = (pi/2) * tanh(theta_role + delta_raw_role)
G = (V.T @ RoPE(K) / 81) * L(phiV_i - phiK_j)
L(delta) = sign(delta) * exp(-abs(delta)), exact tie=0
```

위상 생성은 FP32이며, 본체의 두 residual RMSNorm과 위상 분기의 두 residual
RMSNorm 모두 제곱 평균을 FP32로 계산한다. eps=1e-5, affine 없음, 입력 dtype으로
반환한다. 위상 분기에서는 각 채널 토큰의 16차원 전체를 정규화한다. 본체의
어텐션 residual 정규화는 기존처럼 FFN 앞에 위치한다. 위상은 각 블록에서 다시
생성하며 토큰에 걸쳐 공유하므로, 위상 입력에 K/V가 들어가도 외적의 토큰 합과
L을 분리한 한 번의 KV GEMM 및 전체 역전파가 정확하게 유지된다.

기존 고정 위상 모델의 모든 파라미터 초기화를 먼저 수행한 뒤 위상 분기를 추가했다.
마지막 scalar readout만 0으로 초기화해 초기 forward를 고정 위상 모델과 정확히
맞춘다. readout은 즉시 gradient를 받지만, 실제 warmup의 첫 스텝은 LR=0이라
2스텝에서 처음 갱신된다. 이후 3스텝부터 encoder/attention/FFN에도 gradient가
전달되는 것을 실제 compiled GPU 실행에서 확인했다. 추가 파라미터는 31,008개,
전체는 8,571,915개다. theta offset은 decay=0, 위상 분기 행렬과 embedding은 decay=1이다.

### 위상 분기의 절대 위치 의존성 점검

사용자가 위치 편향 가능성을 제기했다. 현재 위상 분기는 이미 공간 RoPE가 적용된
K와 원래 V를 받고, 각 채널의 81개 토큰 값을 Linear(81,16)으로 사영한다. 이
사영의 열마다 서로 다른 가중치가 있으므로 추가적인 절대 칸 위치 의존성이 생긴다.
행·열·박스 단위의 구조적 가중치 공유나 스도쿠 변환에 대한 불변성은 보장하지 않는다.
channel_embedding은 공간 embedding이 아니라 K/V 역할 및 채널의 식별 embedding이다.
위상 생성기에 별도의 절대 위치 정보가 반드시 필요하다는 근거는 없으며, 이 선택은
모델의 설계 가정이다. 위치 민감성 자체가 성능 저하의 증거라는 뜻은 아니다.

13,671스텝 raw 체크포인트와 저장 carry의 8개 퍼즐에서, 이미 RoPE를 적용한 K/V
쌍의 토큰 순서를 위상 입력에서만 함께 재배열했다. 기존 V.T@RoPE(K)/T는 상대
오차 2.2e-7 이내로 보존되지만, 사영 행렬의 절대 슬롯과 대응되는 내용이 바뀐다.
행 0/1에 해당하는 슬롯을 교환하면 L 부호의 5.17%, 첫 두 band에 해당하는 슬롯을
교환하면 32.70%, transpose 슬롯 재배열에서는 17.63%가 바뀌었다. 적용된 G의
상대 L2 변화는 각각 0.605, 1.200, 0.973이었다.

이 검사는 위상 분기의 슬롯 순서 민감도를 분리한 것이며, 실제 퍼즐 전체에 유효한
스도쿠 변환을 적용한 정확도 검사가 아니다. 위상 입력의 RoPE만 제거했을 때도
29.51%의 L 부호가 바뀌었지만, 학습된 입력 분포를 바꾸는 조작이므로 RoPE 제거가
학습 성능을 개선한다는 근거로 사용할 수 없다. live 학습에는 변경을 가하지 않았다.
기록은 [channel_phase_position_sensitivity.json](2026-10-05/channel_phase_position_sensitivity.json)에 있다.

## 후속 실험: 81차원 전체 공동활성으로 채널 위상 생성

사용자 요청으로 `phase_channel_gram_exp_current_only`를 추가했다. 기존 81→16
활동 사영과 위상 Q/K 사영을 제거하고, RoPE(K)와 V의 전체 공간 활동 패턴으로
채널 어텐션 점수를 직접 계산한다. Value 경로와 scalar readout에 칸별 가중치를
다시 넣지 않도록, 채널·역할 식별 embedding을 Value로 사용한다.

```text
Z = concat(RoPE(K).T, V.T)                 # [B,H,208,81]
S = Z @ Z.T / 81                         # full-profile coactivity, [B,H,208,208]
A_phase = softmax(S, dim=-1)
E = channel_embedding                    # [H,208,16], no spatial slots
u = RMSNorm(E + out(A_phase @ value_proj(E)))
y = RMSNorm(u + down(GELU(up(u))))         # 16 -> 64 -> 16
delta_raw_K, delta_raw_V = split_KV(readout(y))
phi_role = (pi/2) * tanh(theta_role + delta_raw_role)
G = (V.T @ RoPE(K) / 81) * L(phiV_i - phiK_j)
L(delta) = sign(delta) * exp(-abs(delta)), exact tie=0
```

16은 전체 81칸 비교 **이후** 교환하는 채널 메시지의 폭이다. 활동을 먼저 16차원으로
사영하는 연산은 없다. 점수에 별도 Q/K 정규화나 학습 온도는 적용하지 않는다.
동일한 토큰 재배열을 이미 RoPE가 적용된 K와 V에 함께 적용하면 Z Z.T가 보존되어
위상과 해당 경로의 gradient도 보존된다. 실제 퍼즐의 위치를 바꾸고 RoPE를 다시
적용하는 변환에 대한 불변성을 뜻하지 않는다. 전체 평균만 보는 생성기와도 다르다.
각 채널의 평균과 RMS가 같아도 채널 간 공동활성이 다르면 위상이 달라질 수 있다.

기존 본체 K/V 사영·RoPE·지수형 창·토큰 공유 위상·KV GEMM은 유지한다. 두 residual
RMSNorm은 본체와 위상 분기 각각에서 attention 뒤, FFN 뒤에 적용한다. FP32
제곱 평균, eps=1e-5, affine 없음, 입력 dtype 복귀 규칙을 따른다. 위상 분기는 FP32다.
마지막 scalar readout을 0으로 초기화해 고정 위상 모델과 같은 초기 함수로 시작하며,
원래 본체와 theta의 초기화 난수 순서를 보존한다. 별도 위상 누적 상태는 없다.

이 실험은 초기 공간 압축과 추가 절대 슬롯 혼합을 함께 제거하는 설계 실험이다.
위상 어텐션의 점수 및 Value 생성 방식도 변경되므로, 단순히 latent width만 바꾸는
한 변수 실험으로 해석하지 않는다. 기존 위치 민감성 관측만으로 이 방식의 성능
개선을 보장할 수는 없다.

CPU 52개 테스트를 통과했다. 신규 검증은 81칸 공통 재배열의 위상 및 gradient
불변성, 평균과 RMS가 같아도 공동활성 차이를 구별하는지, 공간 슬롯 파라미터가
없는지, 토큰 반복 시 평균 Gram이 보존되는지 확인한다. 초기 고정 위상 일치,
직접 pair 합산과 GEMM의 전체 gradient 일치, 실제 residual norm 위치와 dtype,
activation checkpoint 재계산, optimizer/EMA/carry 저장·재개 및 최근 3개 보관도
포함한다. 로그는 [channel_gram_phase_tests.log](2026-10-05/channel_gram_phase_tests.log)다.

## 설계 고찰: 각 토큰 쓰기의 독립적인 합을 복원하기

사용자는 작은 위상 보정 계수로 완화하는 접근보다, 고정 위상에서 사라진 구조적
성질을 정의하고 이를 포함하는 설계를 요구했다. 여기서 확인한 성질은 **현재 블록의
입력 hidden 행들을 주어진 입력으로 볼 때, 각 토큰의 쓰기를 독립적으로 계산한 뒤
합할 수 있다는 것**이다. 모델 전체가 전역 문맥과 독립적이라는 뜻은 아니다. 각
hidden은 이미 이전 블록의 전역 정보를 담는다.

`a_n = v_n k_n.T` (k에는 기존 RoPE 적용)라고 쓰면 고정 위상은
`G0 = mean_n(L0 * a_n)`이다. 현재의 세 동적 위상 구성은 모두 한 퍼즐 전체에서
생성한 `L(h_1,...,h_T)`를 사용하므로, `G = L(h_1,...,h_T) * mean_n(a_n)`이다.
상태 하나에서 L을 합 밖으로 꺼내는 대수적 항등식은 여전히 정확하지만, 서로 다른
입력 부분집합에서 독립적으로 생성한 쓰기를 합하는 성질은 보장하지 않는다.
한 토큰 n이 L을 바꾸면, m!=n인 다른 토큰의 기여 `L*a_m`까지 변한다.

```text
현재: dG/dh_n = [ L * da_n/dh_n + (sum_m a_m) * dL/dh_n ] / T
국소: dG/dh_n = [ L_n * da_n/dh_n + a_n * dL_n/dh_n ] / T
```

곱의 미분법칙 자체가 잘못됐다는 주장이 아니다. 두 번째 항에서 변조되는 대상이
퍼즐 전체의 쓰기인지 해당 토큰의 쓰기인지가 다르다. 이 전역 결합을 성능 저하의
원인 후보로 삼을 수 있지만, 실제 학습 실패의 원인임을 입증한 것은 아니다.

제안은 `phi_role[n,c] = F_n(base_phi_role[c])`로 바꾸는 것이다. `F_n`은 각 토큰의
현재 K/V 또는 hidden에서 생성한 단조 증가 함수이고, 동일한 토큰·헤드에서는 K와
V에 같은 함수를 적용한다. 학습 가능한 base_phi는 기존 고정 위상의 값이다.
모든 토큰에서 `F_n(x)=x`이면 기존 고정 위상 모델이 정확히 포함된다. 각 토큰의
위상은 크게 움직일 수 있지만 K/V 사이의 기본 순서는 보존된다. 이는 상태에 따라
위상 순서를 자유롭게 뒤집는 표현력은 의도적으로 제한하는 선택이다. base_phi의
순서는 파라미터 학습으로 바뀔 수 있으며, 여기서 보존하는 것은 파라미터가 같을 때
입력 토큰마다 달라지지 않는 순서다.

```text
M_plus[i,j]  = (base_phiV[i] > base_phiK[j])
M_minus[i,j] = (base_phiV[i] < base_phiK[j])
G = ( M_plus  * ((V * exp(-phiV/tau)).T @ (K * exp( phiK/tau)))
    - M_minus * ((V * exp( phiV/tau)).T @ (K * exp(-phiK/tau))) ) / T
```

이 식은 `mean_n(V_ni K_nj sign(phiV_ni-phiK_nj) exp(-abs(delta)/tau))`와 정확히 같다.
순서 mask가 토큰에 무관하므로 두 지수 절반을 각각 하나의 GEMM으로 분리할 수
있다. 원래 signed exponential 창, exact tie=0, 전체 phase gradient를 유지한다.
쓰기 GEMM은 1회에서 2회가 되고, T*dh*dh 전체 pair 텐서를 만들 필요가 없다.
실제 GPU 속도나 학습 성능을 측정한 결과는 아직 없다.

독립적인 CPU 대수 검증은 `lt/probe_local_phase_warp.py`에 있다. 원래 phase 축을
8구간으로 나누고, token-local Linear([K_n,V_n],8)의 softmax로 각 구간의 양의 길이를
정한 뒤 누적·선형 보간한다. 입력 사영을 0으로 초기화하면 항등 함수이고, 이는
공간 81칸을 압축하는 구성이 아니다. 이 probe는 학습 모델에 설치되지 않았다.

FP64 검증 결과는 다음과 같다.

본체 attention residual과 FFN residual의 두 RMSNorm은 이 제안에서도 유지한다.
live 모델·설정·학습 프로세스는 변경하지 않았다.

관련 비교로 [Mamba-3 §3.2](https://arxiv.org/html/2603.15569v1#S3.SS2)는 복소 상태
전이를 실수 2x2 회전 및 B/C의 일관된 누적 회전으로 구현한다. 현재 모델의
signed exponential K/V 채널 창은 해당 회전 연산과 동일하지 않다. 위 제안의
근거는 Mamba-3의 실험 성능을 이전하는 것이 아니라, 유지할 대수적 구조를 명시한
상태 의존성을 설계한다는 접근이다.

## 후속 학습: 칸별 단조 위상 변환과 두 KV 행렬곱

사용자 승인으로 `phase_local_warp_exp_current_only`를 실제 학습 variant로 구현했다.
`LocalMonotonePhaseWarp`와 `LocalWarpExponentialPhaseCurrentReadInner`를 추가했으며,
기존 실행 중인 Gram 위상 variant의 forward는 변경하지 않았다.

각 토큰·헤드의 `[RoPE(K_n), V_n]` 208차원에 공유 Linear(208,8,bias=False)를 적용한다.
8개 logits의 softmax로 위상 축 [-pi/2,pi/2]의 각 구간 길이를 정하고, K/V의 학습된
기본 위상에 같은 선형 보간 함수를 적용한다. 8은 공간 칸을 압축하는 차원이 아니라
위상 축의 구간 수다. 위상 생성기는 칸·헤드·퍼즐의 입력을 섞지 않으며, 가중치만
공유한다. 입력 hidden은 기존 recurrent block에서 얻은 문맥을 그대로 포함한다.

```text
base_phi_role = (pi/2) * tanh(theta_role_raw)          # [H,dh]
logits_n = Linear_208_to_8(concat(RoPE(K_n), V_n))
interval_lengths_n = pi * softmax(logits_n)
phi_role[n,c] = F_n(base_phi_role[c])                  # [B,H,T,dh]
M_plus  = (base_phiV[:,None] > base_phiK[None,:])
M_minus = (base_phiV[:,None] < base_phiK[None,:])
G = ( M_plus  * ((V*exp(-phiV)).T @ (RoPE(K)*exp(phiK)))
    - M_minus * ((V*exp(phiV)).T @ (RoPE(K)*exp(-phiK))) ) / T
read = RoPE(Q) @ G.T
```

위상 사영은 0으로 초기화한다. 학습 전 위상이 FP32에서도 기본 위상과 정확히
같도록, 보간을 항등 함수에서의 knot 변위로 계산한다. 원래 모델과 theta의 모든
난수 초기화를 먼저 수행하고 새 사영을 추가한다. 두 GEMM의 연산 결합 순서 차이로
초기 G/read의 FP32 값에는 작은 반올림 차이가 있을 수 있으므로 bitwise forward
일치로 설명하지 않는다. 로컬 사영에는 첫 backward부터 gradient가 있으며, 기존
warmup과 같이 첫 optimizer step은 LR=0이다.

정확한 창은 tau=1의 signed exponential이고, 같은 기본 위상은 0이다. 부호는
bounded base_phi에서 계산하여 모든 토큰에 공유한다. 매우 가까운 위상을 FP32로
각각 반올림한 뒤 순서를 다시 판정하지 않는다. 단조성의 수학적 성질과 부호 마스크를
함께 이용하며, 기본 위상 순서는 파라미터 학습으로 바뀔 수 있다. 상태별 자유로운
순서 반전은 허용하지 않는다. FP64 직접 합산과 전체 gradient 일치도 검증했다.

본체의 attention residual 직후와 FFN residual 직후에 RMSNorm을 각각 적용한다.
FP32 제곱 평균, eps=1e-5, affine 없음, 입력 dtype 복귀 조건을 실제 forward에서
확인했다. 새 위상 분기는 단일 Linear와 단조 변환으로 구성되므로 추가 attention이나
