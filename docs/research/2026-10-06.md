## 1. tanh·sech 창의 fused 커널

### 배경

어제 채택한 사인 4성분 창은 매끄럽게 만든 목표 창의 근사였다. 원래 부호 지수창
`sign(δ)·exp(−|δ|)`은 토큰마다 위상이 다르면 GEMM으로 분해되지 않고, 부호 경계를 넘는
유한 위상 변화에서 gradient 예측이 깨진다. 사용자는 원점 대칭, 원점 기울기 1,
`±A·exp(∓Δt/τ)` 꼬리를 갖는 해석적 창을 직접 쓰는 방향을 제안했다.

### 창과 수식 트릭

`L(δ) = tanh(δ)·sech(δ)`: 홀함수, 원점 기울기 1, peak 1/2(δ = asinh 1), 꼬리 `2e^{−|δ|}`.
같은 rank의 사인 근사 오차는 현재 ε=0.5 창보다 약 30배 작지만(R=4: 0.05%/0.54%),
이번에는 근사 없이 직접 계산했다.

`r = e^δ, p = r²`이면 `L = 2r(p−1)/(p+1)²`, `L' = 2r(−p²+6p−1)/(p+1)³`.
`r = e^{φV}·e^{−φK}`가 분리되므로 토큰·채널별로 `A = V e^{φV}`, `P = e^{2φV}`,
`B = K e^{−φK}`, `Q = e^{−2φK}`를 미리 계산하면 쌍마다 exp 없이 역수 1회와 FMA 몇 번이면 된다.
커널은 A, P, B, Q의 gradient를 내고 autograd가 나머지를 연결한다.

- forward: (i,j) 타일에서 토큰을 순회하며 외적 누적.
- backward: 행/열 방향을 각각 한 커널로, [D,T] 전치 레이아웃에서 atomic 없이 누적.
- `torch.library.triton_op`으로 등록해 compile(fullgraph)에서 그래프가 끊기지 않는다.
- compile이 `num_warps` 실행 인자를 무시하는 문제를 발견해 단일 Config autotune으로 고정했다.
- 초기 구현은 compile 시 backward가 117ms였다(atomic, 비연속 로드). 재설계 후 연산 7.24ms.

검증: FP64 직접 pair 대비 값·K·V·위상 gradient 상대 오차 4e-7 이하, compile과 eager 일치.
자세한 내용과 벤치마크: [tanhsech_kernel/README.md](2026-10-06/tanhsech_kernel/README.md).

| 모델 (RTX 3090) | 연산 ms | 학습 초/step | peak MiB |
| --- | ---: | ---: | ---: |
| 고정 지수 창 | 2.13 | 0.136 | 1,303 |
| tanh·sech 정확 | 7.24 | 0.189 | 2,701 |

## 3. 위상이 상태에 따라 움직이지 않음

14,000스텝 ×2 체크포인트: gain |a| 평균 0.010, 최대 0.083. 토큰 간 위상 표준편차 약 0.01 rad
(위상 크기 0.38 rad의 2~3%), θ만 쓸 때 대비 순서 반전 0.88%. **위상은 사실상 채널별 학습 상수다.**
어제 "상태 의존 자유위상"이라고 부른 구조는 학습된 모델에서 실현되지 않았다. 그 결과 창은
토큰과 무관한 채널 쌍 마스크 `M_ij = L(θV_i − θK_j)`로 작동한다.

gain을 weight decay에서 뺀 런(7,175스텝까지)에서도 gain은 0.010이었다. 이 크기에서 decay의
힘(lr·wd·|a| ≈ 1e-6/step)은 Adam 갱신(≈1e-4/step)보다 100배 작으므로, gain을 붙잡는 것은
decay가 아니라 일관된 gradient 방향의 부재로 본다. 학습 곡선도 기준과 같았다.

## 6. 발견: 정규화가 의도와 다르게 구현됨

사용자가 "RMSNorm"이라고 부른 것은 v1.7의 Φ였다.

```text
의도 (v1.7 Φ, γ=1/d):    Φ(h) = h / √(1 + mean(h²))          eps = 1
10-04 이후 구현 (URM):    RMSNorm(h) = h / √(1e-5 + mean(h²))   eps = 1e-5
```

| | Φ (eps=1) | 현재 RMSNorm |
| --- | --- | --- |
| 출력 크기 | 입력 RMS r → r/√(1+r²) < 1 | 항상 RMS 1 (구면) |
| 작은 h | 거의 그대로 | 크게 증폭 |
| 성질 | 부드럽게 수축 | 크기 정보를 버리는 사영 |
| 위치 | v1.7: 블록 끝 1회 | attention 뒤, FFN 뒤 각 1회 |

10월 4일 커밋 `5326bf3`에서 `AGENTS.md`와 `docs/research/2026-10-04/README.md`에
"URM과 같이 `x * rsqrt(mean(x**2) + 1e-5)`"로 규칙이 기록됐고, 이후 모든 신규 구조
(`URMNormCurrentReadInner`를 상속하는 위상·자유위상·Hebbian 런)에 적용됐다.
10월 3일까지의 KV 모델은 `lt/train.py`의 블록 끝 Φ를 썼다.

하네스와 하이퍼파라미터가 같다는 것이 확인된 뒤 남은 가장 큰 차이이므로, 평가 출렁임의
유력한 원인 후보다. 아직 실험으로 확인하지 않았다.
