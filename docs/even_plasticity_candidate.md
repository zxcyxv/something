# 후보: 빠른 위상 전달과 학습 가능한 짝수 가소성 창

## 현재 판단

이 후보는 `w-only`, `Q=K`, `Q/K/V 사영 공유`, `β=0` 고정 중 어느 것도 아니다.
빠른 기저 전달과 두 사영은 유지한다. 가소성 창의 대칭 부분을
실수 계수로 직접 표현하고, 결합 기억의 대칭성을 이용해 상태 저장량을 줄인다.

활동 모델의 근거는 [위상 집단 활동 유도](phase_population_v11.md)에 있다.
현재까지 구현·미분·학습 하네스의 동작과 작은 체크포인트 진단은 확인했다.
**본 규모 재학습 성능과 GPU 속도는 검증하지 않았다.**

## 1. 구조

위치 회전까지 포함한 정규화 주소를 z, 정규화된 내용 벡터를 v̂라 두면

\[
F_{in,k}=D_{in}\,\langle\hat v_{i,k},\hat v_{n,k}\rangle
\sum_j c_j\operatorname{Re}[z_{i,j,k}\bar z_{n,j,k}],
\]
\[
p_k=(1-\eta)p_{k-1}+\eta F_k,\qquad
J_k=b\,a^\psi_k+p_k,
\]
\[
h_{k+1}=\Phi(q_k+P^T J_k v_k).
\]

c_j는 양수나 음수가 될 수 있는 학습 가능한 창 계수다.
j는 학습된 위상 채널이며, 실제 시간 주파수라고 주장하지 않는다.
ψ는 원본처럼 빠른 전달에 남는다. b와 η도 학습한다.

원본에서 변환하는 초기값은

`b=1−λ`, `c_j=λg cos β_j`, `p=λ sym(w)`

이다. 원본의 **모든 가소성 전달을 대칭화한 모델**과 동치다.
원본 전체나, 기존의 ‘대칭 과거 보정만 유지’ 실험과 동치인 것은 아니다.
첫 쓰기 초기화는 원본처럼 `p_1=F_1`로 유지한다.
초기화까지 바꾸면 별개의 가설이 섞이므로 이번 후보에서는 변경하지 않았다.

## 2. 각 β보다 실수 c를 직접 학습하는 이유

원본 한 채널의 위상 커널을 짝수·홀수 부분으로 쓰면

\[
\cos(\delta+\beta)=\cos\beta\cos\delta-\sin\beta\sin\delta.
\]

β≈0에서는

\[
\cos\beta=1-\frac{\beta^2}{2}+O(\beta^4),\qquad
\sin\beta=\beta+O(\beta^3).
\]

따라서 **각 β를 조금 움직이면 홀수 부분은 1차로 바뀌지만 짝수 부분은
2차로만 바뀐다.** 대칭 가소성 창의 채널별 크기를 바꾸려는 목적에는
불필요하게 홀수 부분을 함께 만들어야 하는 좌표계다.
공통 gain은 모든 채널의 크기를 함께 바꾸므로 이 문제를 완전히 해결하지 않는다.

직접 계수 c를 쓰면 `d(c cos δ)/dc=cos δ`이므로 대칭 창을 1차로 조절한다.
이것이 단순히 매개변수 이름을 바꾼 것 이상의 학습 가설이다.
원본의 추론을 사후에 대칭화했을 때 성능이 유지되는가와는 다른 주장이다.

CPU의 합성 커널 맞추기 예제에서는 동일한 초기 커널과 손실 26.6393에서
다음 결과를 얻었다. 목표는 채널별 계수가 다른 대칭 커널이며,
β=0에서 공통 gain을 먼저 최적화한 상태다.

| 좌표 | 손실 기울기 크기 |
|---|---:|
| 원본 각 β | 7.55e−16 |
| 원본 공통 gain | 3.55e−15 |
| 직접 실수 계수 c | 44.4742 |

이 예제는 각 좌표의 제한을 보여 주는 구성적 반례다.
실제 체크포인트의 β가 모두 0이라는 주장이나, 실제 학습에서 같은 정체가
발생했다는 증거는 아니다. 내용·주소·기저·MLP도 학습되는 전체 문제에서는
다른 경로로 손실을 줄일 수 있으므로 재학습 비교가 필요하다.

## 3. 상태·매개변수·연산

대칭 p는 위 삼각형과 대각선만 저장한다.

| 한 문제의 결합 상태 | 원본 | 후보 |
|---|---:|---:|
| 실수 원소 수, H=8,N=81 | 52,488 | 26,568 |
| FP32 저장량 | 209,952 bytes | 106,272 bytes |

이는 **결합 carry의 49.38% 감소**다. 전체 학습 메모리가 절반으로 줄어드는 것은 아니다.
현재 구현은 전달할 때 대칭 행렬을 복원한다. 이 비용 때문에 연산 속도가
개선된다고 아직 말할 수 없다.

학습 매개변수는 7,155,243→7,155,235로 8개만 줄었다.
따라서 주된 단순화는 작은 파라미터 수 감소가 아니라 가소성 창의 표현과
지속 상태의 구조다. value 사영의 유용한 기하를 없애서 얻은 감소도 아니다.

## 4. 검증

- 저장된 152·192블록 상태에서 각각 8블록 연속으로 대칭 가소성 기준식과 비교:
  은닉 상태 최대 오차 8.0e−15 미만, 쓰기 목표 오차 7.8e−16 미만.
- 작은 모델의 전체 3블록 경로를 통한 c의 역전파와 중심 수치 미분 비교:
  오차 1.73e−11 미만. ψ·주소·value·η·b에도 유한한 비영 기울기가 흐른다.
- 작은 무작위 토큰 맞추기 20 SGD 스텝에서 손실 2.3468→1.2958.
  이는 학습 가능성에 대한 실행 점검이며 스도쿠 성능 실험이 아니다.
- 실제 학습 하네스의 stablemax 손실·AdamATan2·희소 임베딩·EMA로 CPU 6스텝 실행.
  새 가소성 계수와 기저 계수의 weight decay 제외를 확인했다.
- 문제 리셋, 체크포인트 저장/재개 후 원시 가중치와 로짓의 정확한 일치를 확인했다.

재현:

```bash
python lt/research_phase_activity.py
python lt/research_even_plasticity.py
python lt/research_even_harness.py
```

## 5. 재학습 없는 16문제 파일럿

사전에 정한 held-out 인덱스 128:144를 사용했다. 앞선 관계 분석의 128문제와
겹치지 않는다. 각 모델을 처음부터 FP32 CPU로 1024블록 실행했다.

| 지평 | 원본 완답 | 후보 완답 |
|---|---:|---:|
| 128블록 / 16세그먼트 | 5/16 | 5/16 |
| 256블록 / 32세그먼트 | 5/16 | 6/16 |
| 512블록 / 64세그먼트 | 5/16 | 6/16 |
| 1024블록 / 128세그먼트 | 6/16 | 6/16 |

최종 해결한 문제 집합도 같았다. 추가 해결한 한 문제는 8블록 간격 관측에서
원본 576블록, 후보 216블록에 처음 완답으로 관측되었다.
최종 칸 정확도는 원본 0.753858, 후보 0.753086이었다.

이 결과로 주장할 수 있는 것은 **이 표본에서 변환이 즉각적인 큰 붕괴를
일으키지 않았고 추가 해결을 유지했다**는 것까지다. 표본이 작고 재학습도
없으므로 정확도·속도 우위나 일반적인 비열등성을 주장하지 않는다.

```bash
python lt/research_even_pilot.py
```

결과는 `runs/even_plasticity_pilot_v11/summary.json`에 있다.

## 6. 다음 비교의 조건

훈련 가능한 후보는 `lt/even_plasticity.py`, 실행 진입점은 `lt/train_even.py`다.
후보의 기본 출력은 `runs/even_v11`이며 원본 train.py와 분리했다.
실제 GPU 학습은 이번 연구에서 실행하지 않았다.

```bash
python lt/train_even.py --preset v1.1 --out_dir runs/even_v11_seed0 --seed 0 --no_compile
```

이 명령은 예시이며 새 학습을 시작한다. 원본 v1.1 체크포인트를 그 명령의
`--resume_from`에 바로 넣을 수는 없다. 후보 체크포인트만 직접 재개할 수 있다.
원본에서의 파라미터 변환은 `from_v11()`로 따로 지원한다.

다음에는 같은 데이터·반복 지평·학습 예산·여러 시드로 원본과 후보를 비교해야 한다.
직접 c를 학습하면 매개변수 좌표가 달라지므로 동일한 학습률이 동일한 유효
커널 변화량을 뜻하지 않는다. 학습률 민감도도 함께 기록해야 한다.
평가에서는 학습 지평의 완답, 연장 지평의 추가 완답, 풀었던 문제의 재오답을
함께 봐야 한다. 그 전에는 이 후보를 기본 아키텍처로 승격하지 않는다.
