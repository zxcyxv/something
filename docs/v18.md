판정할 수 있는 것:

- **β의 이동은 원인이 아니다.** 100k 모델에 200k의 β를 넣으면 오히려 좋아진다. 200k에 100k의 β를 넣었을 때의 붕괴는 200k 행렬이 200k β에 적응한 결과로 본다.
- **η와 λ·g는 저하의 일부를 운반한다.** 교환 방향과 무관하게 일관된다. η는 주로 외삽을, λ·g는 seg16 테스트 성능도 운반한다 (200k + 100k의 λ·g에서 seg16 280→304).
- **나머지는 행렬 쪽이다.** 24개 스칼라를 되돌려도 200k의 최고치는 348로 100k의 410에 못 미친다. 행렬은 10k마다 크게 회전해 100k와 200k 사이에 호환되지 않으므로 교환으로 분리할 수 없다.

### 1.4 해석 (측정이 아니라 추론)

- **세그먼트 경계의 detach 때문에 gradient는 8블록 안의 효과만 본다.** η에 대한 gradient는 `w_prev − G`로 주어지지만, 그 w_prev를 만든 과거 η나 다음 세그먼트에 대한 효과는 보지 못한다. 기억 시간이 20~100블록인 모델에서 학습 목적은 긴 기억을 과소평가하고, 짧은 기억 쪽으로 기울 수 있다.
- **AdamATan2는 원소마다 스텝당 약 lr만큼 움직인다.** 스칼라는 작지만 부호가 일관된 학습 gradient에도 최대 속도로 표류한다. 헤드당 3개의 스칼라가 모든 블록·칸 쌍에 같은 비율을 적용하므로, 학습 퍼즐 분포에 맞춘 이동이 전부에 반영된다.
- **weight decay는 이 설정에서 해를 단순화하는 규제가 아니다.** `wc`는 주소 정규화 때문에 크기가 함수에 영향을 주지 않으므로, decay는 노름을 줄여 유효 학습률만 키운다. lr이 상수(`lr_min_ratio=1.0`)라 decay와 갱신이 균형을 이룬 상태에서 행렬이 계속 회전한다. 감쇠 없는 스칼라에는 decay가 걸리지 않는다.

## 2. 설계

### 2.1 SSM 형태로 본 기존 가소성

```text
쓰기  w_k = A ⊙ w_{k−1} + B ⊙ G_k          v1.71: A = 1−η, B = η·g   (헤드당 상수)
읽기  a_eff = (1−C) ⊙ a_k + C ⊙ w_k         v1.71: C = λ              (헤드당 상수)
G_k = a^β(ẑ; β, θ, α) ⊙ agree               쓰기 목표. v1.8 에서도 그대로
```

상태는 칸-칸 관계 행렬 w, 입력은 쓰기 목표 G, skip 입력은 순간 읽기 커널 a다.
v1.8은 A·B·C를 selective SSM처럼 현재 입력(칸 상태)에서 생성한다.

### 2.2 v1.8 식

```text
q_t = h_t + √d · inj_t                       블록의 주입 후 상태 (step 의 입력)
s_t = sel_w · q_t + bias ∈ R^{3×H}            [s^Δ, s^g, s^λ], 헤드마다

Δ_t   = softplus(s^Δ_t)
A_tn  = exp(−(Δ_t + Δ_n)/2)                  기억 유지. 쌍 대칭 (= √(A_t A_n))
g_tn  = g_max · σ((s^g_t + s^g_n)/2)          쓰기 이득. 쌍 대칭, 상한 g_max = 4
λ_t   = σ(s^λ_t)                              읽는 칸 t 의 기억 보간

w     = G                                     퍼즐의 첫 블록 (fresh)
w     ← A ⊙ w + (1−A) ⊙ g ⊙ G                 그 외
a_eff = (1−λ_t) a_t· + λ_t w_t·
```

설계 근거:

1. **Δ 하나가 보간 정도를 정한다.** Δ→0이면 A→1, 1−A→0이 되어 그 쌍의 기억이 동결된다. Δ가 크면 현재 목표로 덮어쓴다. `settling_v11`의 관측(정착 뒤에는 w가 거의 변하지 않아야 하고, 교환 순환을 깰 때는 관계를 다시 써야 함)을 상태에 따라 고르는 장치다. 기억 시간 1/Δ가 블록마다 달라질 수 있다.
2. **B = (1−A)·g로 볼록결합 구조를 유지한다.** `1−A = −expm1(−Δ)`는 Mamba의 ZOH 이산화와 같은 꼴이다. g에 상한을 두면 `|w| ≤ g_max · max|G|`가 유지된다. v1.71에서 g는 0.84→1.20으로 커졌다. A와 B를 독립으로 풀지 않는다.
3. **쓰기 게이트는 쌍 대칭이다.** 칸마다 따로 게이트를 걸면 w_tn과 w_nt의 갱신률이 달라져 반대칭 성분이 새로 생긴다. 대칭 결합이면 G의 대칭 성분은 w의 대칭 성분으로만 들어간다. `memory_correction_v11`에서 외삽을 지탱한 것은 대칭 과거 보정이었다. β가 만드는 반대칭 성분은 지금처럼 G를 통해 w에 들어간다.
4. **읽기 게이트는 행 단위다.** 이 칸이 지금 기억을 얼마나 믿을지는 읽는 쪽이 정한다. a는 ψ 때문에 원래 비대칭이다.
5. **게이트는 FP32로 계산한다.** BF16에서는 1−A의 해상도가 약 0.004라 η≈0.01의 긴 기억이 뭉개진다. `select_gates`는 autocast를 끄고 계산한다.
6. **delta rule은 쓰지 않는다.** `w ← w + β(G − w)`는 위 EMA와 같다. 목표가 쌍 행렬 전체라서 키가 겹칠 때의 간섭을 교정할 일이 없다.

### 2.3 파라미터

| 파라미터 | 크기 | 초기값 | weight decay |
|---|---|---|---|
| `sel_w` | 3×H×d | 0 | 1.0 |
| `dt_bias` | H | `inv_softplus(−log(1−η_init))` | 없음 |
| `gsel_bias` | H | `logit(g_init / g_max)` | 없음 |
| `lsel_bias` | H | `logit(λ_init)` | 없음 |

`eta_raw`, `gain_raw`, `lam_raw`는 없어지고, `beta`, `mu_rho_raw`, `mu_omega`는 v1.71과 같다.
추가 파라미터는 3×8×832 + 24 = 19,992개다.

`sel_w = 0`이면 모든 칸에서 게이트가 헤드별 상수이고, 바이어스를 v1.71 값으로 두면 v1.71과 같은 함수다.
`sel_w`에 걸린 weight decay는 0, 즉 헤드별 상수 게이트 쪽으로 당긴다. β를 0으로 끌어 대칭 연산으로 만드는 decay와 달리,
필요 없는 선택성만 지우는 규제다. 새 학습에서도 난수 소비가 같아서, 같은 seed이면 공유 파라미터의 초기값이 v1.71과 같다.

## 3. 학습 하네스 옵션

모두 `lt/train.py`의 CFG 키다. 각 옵션을 따로 켜고 끌 수 있다.

| 키 | Kaggle `CFG` | `DEFAULT_CFG` | v1.71 동작 | 내용 |
|---|---|---|---|---|
| `plastic_select` | True | True | False | 위 게이트 |
| `select_g_max` | 4.0 | 4.0 | — | 쓰기 이득 상한 |
| `init_from` | v1.71 100k 경로 | None | None | 가중치 가져오기 (아래) |
| `lr_rewarm_start` | 100000 | None | None | 이 스텝부터 lr 재가열. None이면 기존 스케줄 |
| `lr_rewarm_steps` | 10000 | 10000 | — | 재가열 길이 |
| `lr_rewarm_from_ratio` | 0.1 | 0.1 | — | 재가열 시작 배율 (lr 1e-4 → 1e-5에서 시작) |
| `lr_min_ratio` | 1.0 | 1.0 | 1.0 | 기존 cosine 스케줄의 하한. 1.0이면 상수 |
| `late_sup_prob` | 0.0 | 0.0 | 0.0 | 후반 감독 확률 (아래) |
| `late_sup_min`, `late_sup_max` | 16, 112 | 16, 112 | — | 추가로 돌릴 세그먼트 수 범위 |
| `nograd_every` | 0 | 0 | 0 | no-grad 선행 블록을 늘리는 간격(스텝). 0이면 끔 (아래) |
| `nograd_start` | 0 | 0 | — | 첫 no-grad 블록이 추가되는 스텝 |
| `nograd_max` | 16 | 16 | — | no-grad 선행 블록 수의 상한 |

**재가열.** `init_from`은 optimizer를 새로 만든다. 새 모멘트로 원래 lr을 바로 쓰지 않도록, `lr_rewarm_start`부터
`lr_rewarm_steps` 동안 lr을 `lr_rewarm_from_ratio`배에서 1배로 선형으로 올리고 이후 유지한다. 기존 스케줄에 곱해지는 배율이다.
100k에서 시작하면 lr은 100k에 1e-5, 105k에 5.5e-5, 110k부터 1e-4다.

처음 구현에는 가소성 스칼라 전용 lr 배율과 100k 이후 cosine 감쇠도 있었으나, 2026-09-28 사용자 결정으로 뺐다.

**후반 감독.** 학습 지평의 마지막 세그먼트(seg16)를 막 마친 배치를, 확률 `late_sup_prob`로 R∈[min, max] 세그먼트 더
gradient 없이 진행하고, 그다음 한 세그먼트(seg 17+R)를 감독한 뒤 새 퍼즐로 넘어간다. 8블록 BPTT는 그대로이며,
감독받는 상태의 분포를 긴 지평으로 넓힌다. 결정은 (seed, step)으로만 정해져 모든 rank에서 같고 재개해도 같다.
그 스텝의 학습 로그 acc/exact는 seg16이 아니라 seg 17+R의 값이다. 비용은 R세그먼트의 forward이며,
`late_sup_prob=0.25`, R 평균 64이면 학습 시간이 대략 20~30% 늘어난다고 추정한다(미측정).

**no-grad 선행 반복.** TRM처럼 세그먼트 앞부분을 gradient 없이 진행하고 뒤의 `blocks_per_seg`(8) 블록만 역전파한다.
블록 수는 `nograd_start`에 1개로 시작해 `nograd_every` 스텝마다 1씩 늘고 `nograd_max`에서 멈춘다
(예: start=100000, every=10000이면 100k에 1, 110k에 2, 130k에 4). 역전파 메모리는 그대로이고 순방향 계산만 늘어난다.
정규 평가·외삽도 마지막 학습 스텝의 깊이를 쓰며, 로그와 외삽 파일에 `no-grad+grad` 블록 수를 적는다.
따라서 같은 seg16이라도 블록 수가 다르므로, 다른 런과는 블록 수를 맞춰 비교한다.
깊이가 바뀔 때마다 `torch.compile`이 한 번 다시 컴파일하며, 재컴파일 한도를 `nograd_max + 8`로 올린다.
`lt/ckpt_npz.load_lt`로 이 런의 체크포인트를 분석할 때는 `nograd_blocks`를 명시해야 같은 깊이가 된다(기본 0).
v1.1에서 1만 스텝마다 no-grad 반복을 1씩 늘린 실험이 기존 기록보다 좋았다는 사용자 보고가 있다(기록은 저장소에 없음).

**`init_from`.** v1.71 또는 v1.8 학습 체크포인트에서 raw와 EMA 가중치를 가져온다. v1.71이면 η·g·λ를 게이트 바이어스로
변환하고 `sel_w=0`으로 둔다(`convert_plastic_state`). optimizer는 새로 만들고, carry는 새로 시작한다.
step과 데이터 커서는 원본을 이어받으므로 원본 런의 같은 구간과 같은 배치를 본다. 구조·데이터 규약 키(`_INIT_KEYS`)가
다르면 거부한다. 출력 폴더에 체크포인트가 있으면 `init_from`보다 재개가 우선한다.
100k는 퍼즐 경계(100000 = 16 × 6250)라서 새 carry로 시작해도 원본과 같은 배치 흐름이다.

**재개 호환.** 새 키가 없는 기존 체크포인트는 v1.71 동작값(`_LEGACY_DEFAULTS`)으로 비교한다.
꺼진 옵션의 하위 값(재가열 없음일 때 `lr_rewarm_steps` 등)은 비교하지 않는다. 다른 판의 체크포인트로는 재개하지 않는다(`model_id` 검사).

## 4. 검증

- `python lt/train.py --selftest`: CPU 11개 그룹 통과. 기존 7개에 더해
  - 0 게이트 v1.8 = 변환한 v1.71 (β 동일), 2세그먼트의 logits·h·w·z
  - 쓰기 게이트 대칭, β=0에서 w 대칭 유지, 읽기 게이트가 칸마다 다름, 게이트·β gradient가 유한하고 0이 아님
  - 후반 감독·재가열 스케줄에서 저장 후 재개가 다음 가중치·carry까지 비트 단위로 같음
  - no-grad 선행 블록: 값은 더 긴 unroll과 같고, gradient는 선행 상태를 detach한 뒤 역전파한 것과 같음
- `python -m unittest lt.test_v18 lt.test_v171 lt.test_milestone_logging lt.test_train_arc`: 24개 통과.
  `test_v18`은 기존 판 preset 보존, 새 키가 없는 v1.71 체크포인트 재개, `init_from`의 raw·EMA 변환과 커서, activation checkpoint 유무의 gradient 일치, 재가열 스케줄, no-grad 스케줄과 깊이가 바뀌는 구간의 정확한 재개를 검사한다.
- 실제 100k 체크포인트 변환 (`lt/check_v18_init.py`, 앞 512문제, seg128):

| 정밀도 | 칸 예측이 처음 달라진 세그먼트 | seg16 완답 v1.71 / v1.8 | 최고 완답 v1.71 / v1.8 |
|---|---:|---:|---:|
| FP32 | 13 | 305 / 305 | 415 / 415 |
| BF16 | 1 | 307 / 304 | 410 / 417 |

  FP32에서는 seg12까지 모든 칸의 예측이 같다. 변환 오차(게이트 값 1e-7 수준)가 재귀 1024블록에서 증폭되어
  이후 개별 칸이 달라지지만 완답 수는 같다. BF16의 차이는 로컬과 Kaggle 사이의 재현 차이(±5퍼즐)와 같은 크기다.
  이 모델은 작은 섭동에 대해 개별 궤적이 빠르게 갈라진다는 것도 함께 확인된다.
- GPU 스모크: 100k에서 `init_from`, `torch.compile`, BF16, 배치 128, `late_sup_prob=1`(R=3)로 24스텝 실행
  (가소성 lr 배율·감쇠 옵션을 빼기 전의 코드).
  100016스텝(seg16) 뒤 3세그먼트를 더 돌리고 100017스텝에 seg20을 감독했다. 저장과 2048문제 평가(1297/2048)까지 완료했다.

## 5. 실험과 결과

모두 v1.71 100k 마일스톤에서 `init_from`으로 시작하고, lr은 1e-5에서 1만 스텝 동안 1e-4까지 올린 뒤 유지한다.
같은 데이터 흐름이므로 원래 v1.71의 100k→140k가 무개입 대조가 된다. 실행은 로컬 RTX 4000 Ada 1장, 배치 128이다.

| 조건 | `plastic_select` | no-grad 선행 블록 | 상태 |
|---|---|---|---|
| 0 (기존 기록) | False | 0 | 원래 v1.71 Kaggle 런 (같은 optimizer, 재가열 없음) |
| B | True | 0 | 132k에서 중단 (`runs/v18_from100k`) |
| B+ng | True | 100k에 1, 1만 스텝마다 +1 | 실행 중 (`runs/v18_nograd_from100k`) |

A(v1.71 + 재가열)와 C(B + 후반 감독)는 실행하지 않았다. lr은 HRM–URM 계보대로 warmup 뒤 1e-4 고정으로 두기로 해서
lr을 바꾸는 대조는 하지 않는다.

정규 평가(held-out 2048, EMA, seg16 완답) 구간 평균:

| 구간 | 원래 v1.71 | B | B+ng |
|---|---:|---:|---:|
| 101k~109k (재가열 중) | 1287 | 1314 | 1353 |
| 111k~123k | 1287 | 1216 | 1254 |
| 111k~131k | 1284 | 1220 | — |

B의 111k~131k 평가: 1284, 1217, 1222, 1183, 1218, 1203, 1183, 1231, 1251, 1207, 1216
(같은 스텝의 v1.71: 1274, 1321, 1255, 1278, 1316, 1287, 1275, 1285, 1280, 1255, 1296).
B+ng의 seg16은 세그먼트당 블록이 더 많다(111k~ 2+8, 121k~ 3+8).

마일스톤 외삽(앞 512문제, seg16 → seg128까지 최고):

| step | 원래 v1.71 | B | B+ng |
|---:|---|---|---|
| 110k | 304 → 403 | 313 → 397 | 311 → 371 |
| 120k | 304 → 393 | 289 → 403 | 302 → 360 |
| 130k | 298 → 371 | 284 → 373 | — |

- 재가열 구간에서는 B와 B+ng가 v1.71보다 높았지만, lr이 1e-4에 도달한 뒤 둘 다 v1.71보다 낮아졌다.
  하락 폭은 B(1314 → 1216)와 B+ng(1353 → 1254)가 비슷하다. 이어 학습에 no-grad 반복을 더해도 하락은 막히지 않았다.
- 110k에서 B의 raw·EMA 테스트 성능은 v1.71과 거의 같았다(앞 512문제 seg16: EMA 313 대 308, raw 171 대 168).
  재가열 구간의 우위는 게이트보다 낮은 lr의 영향으로 보인다.
- 110k의 B 게이트는 이미 선택적이었다(헤드에 따라 칸 쌍 사이 η 편차가 평균의 약 70%). 헤드 평균은 v1.71이 100k→200k에
  표류한 방향(헤드 1·2·3·8 기억 짧아짐, 헤드 4 거의 동결)으로 1만 스텝 만에 이동했다.
- 학습 배치 완답은 B와 v1.71이 같은 수준이라(110k~117k 약 0.87), B의 테스트 하락은 일반화 격차의 증가다.

## 6. 한계

- 선택적 게이트는 표현력을 바꾸는 변경이다. 1,000퍼즐 과적합과 8블록 신용할당은 그대로다. 게이트의 자유도가 오히려 짧은 기억을 더 쉽게 고르게 할 수 있으며, 이를 겨냥한 것이 조건 C다.
- 게이트 입력은 주입 후 상태 q뿐이다. 두 칸의 관계나 반복 사이의 변화 같은 쌍·시간 정보는 보지 않는다.
- 행렬의 계속되는 회전(§1.2)은 이번 판에서 다루지 않는다. lr 감쇠나 `wc`의 스케일 불변성 처리(노름 고정 등)는 다음 후보로 남긴다.
- 1.4의 해석들은 교환 실험과 파라미터 궤적에서 추론한 것이며, 원인을 분리한 실험으로 확정한 것이 아니다.

## 7. 실행

Kaggle: `lt/train.py` 전체를 셀 하나에 붙여넣는다. `sudoku_lt_1k.npz`와 v1.71 `step_100000.pt`를 Input에 연결하고,
맨 위 `CFG['init_from']`을 그 경로로 맞춘다. 처음부터 학습하려면 `init_from=None`, `lr_rewarm_start=None`, `max_steps=None`으로 바꾼다.
조건 A는 `plastic_select=False`, 조건 C는 `late_sup_prob=0.25`로 바꾼다. 출력은 `lt_v18` (v1.71이면 `lt_v171`)이다.

로컬:

```bash
python lt/train.py --selftest
python -m unittest lt.test_v18 lt.test_v171 lt.test_milestone_logging lt.test_train_arc
python lt/check_v18_init.py runs/v171_kaggle/lt_v171/milestones/step_100000.pt --fp32
python lt/train.py --config runs/v18_from100k/run_config.json   # 조건 B 로컬 실행 설정 (init_from, 재가열, 140k)
```

`lt/probe_param_swap_v171.py`(파라미터 군 교환). 결과는 `runs/v171_kaggle/`에 저장되며 Git에 포함하지 않는다.
