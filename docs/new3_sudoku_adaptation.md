# 새코드3 스도쿠 적용 설계와 증강 검토

검토 대상은 루트의 `새코드3.txt`다. 아래 분석을 바탕으로 `lt/new3.py`와 `lt/train_new3.py`에 스도쿠 모델과 학습기를 구현했다. 실행 방법과 실제 기본값은 [학습 안내](new3_training.md)를 참고한다. 업로드한 원본 파일은 보존했다.

## 결론

현재 구조는 **숫자 이름 바꾸기에는 등변적**이다. `puzzle_emb_ndim=0`을 유지하면 숫자 치환 증강을 생략할 수 있다. 동일한 퍼즐에 숫자 이름만 바꾼 예제는 이상적인 정확 연산에서 같은 loss와 같은 공유 파라미터 gradient를 만든다. 반면 현재 코드에는 행·열·밴드·스택 교환이나 전치에 대한 등변성이 없으므로 공간 증강은 유지한다.

다만 사용자가 최종 선택한 첫 실험은 **현재 데이터와 증강을 그대로 유지**한다. 숫자·공간 증강 모두 켜고 `num_aug=1000`을 사용한다. 숫자 치환 생략은 가능한 별도 실험이며, 공간 증강까지 제거하려면 위치 표현과 메모리 업데이트를 추가로 바꿔야 한다.

## 스도쿠 입출력과 첫 실험 설정

| 항목 | 설정 / 처리 |
|---|---|
| 격자 | `grid=9`, `seq_len=81` |
| 입력 토큰 | 기존 데이터 로더 유지: 원본 빈칸 0 → 토큰 1, 숫자 1~9 → 토큰 2~10, 토큰 0은 예약 |
| 심볼 축 | `vocab_size=11`: 특수 2개 + 숫자 9개 |
| 은닉 상태 | `[B, 11, 81, 256]`; 모든 숫자 채널이 같은 초기 벡터와 파라미터 사용 |
| 반복 | 사용자 지정 기본값: `loops=1`, `blocks_per_seg=8`, `num_layers=1`. 한 배치에서 한 번 갱신하고 다음 배치에서 상태 초기화 |
| 블록별 감독 | `block_supervision="last"`; `all`은 다른 실험 요인 |
| 숫자별 편향 | `puzzle_emb_ndim=0`; 숫자별 `pe_color` 추가 금지 |
| 메모리 | 첫 기준 모델에서는 원본 DeltaMemory 유지 |
| MoE | 최초에는 원본 expert 수 및 모든 expert 활성 상태 유지; 활성 수 스케줄은 별도 요인 |
| 정답 채점 | 첫 비교는 기존 11채널 loss/readout 유지. 숫자 9채널로 출력 제한하거나 힌트를 강제로 고정하는 처리는 별도 비교에서 양쪽 모델에 동일 적용 |
| 데이터 | 같은 1,000개 학습 퍼즐 / 2,048개 평가 퍼즐. 숫자·공간 증강 ON, `num_aug=1000` |
| 평가 | EMA seg1 및 동일 퍼즐의 seg128/256 외삽; seg1 기준 오답 감소율, 완답률, 힌트 훼손, 제약 위반을 함께 기록 |
| 배치 | 학습·평가 모두 128. 현재 구현은 단일 GPU, gradient accumulation 없음. batch 1 설정은 거부 |

현재 embedding 코드는 앞 두 채널을 특수 취급한다. `vocab_size`만 9로 바꾸면 두 숫자가 특수 채널이 되어 숫자 전체의 대칭이 깨진다. 숫자 9채널만 쓰려면 빈칸/힌트 표시를 별도로 설계해야 하므로, 우선 11채널 인코딩을 유지한다.

새코드1/v1.1과 파라미터 및 상태 구조가 다르므로 해당 80k 체크포인트를 그대로 이어 학습할 수는 없다. 새코드3 실험은 별도 초기화가 필요하다. 같은 세그먼트/블록 수가 같은 FLOPs를 뜻하지도 않는다. 이 모델은 각 칸마다 11개 상태를 가지고 두 축의 attention을 수행한다.

## 숫자 대칭이 성립하는 이유

숫자 9개만 재배열하고 특수 토큰 0, 1은 고정하는 순열을 π라 하자. 입력 숫자를 π로 치환하면 은닉 상태의 숫자 축도 같은 순열로 이동한다.

1. `embed_common`은 모든 숫자에 공유되고, 입력 one-hot의 위치만 달라진다.
2. PositionAttention은 숫자 채널마다 같은 q/k/v/out 가중치와 같은 위치 인코딩을 사용한다.
3. SymbolAttention에는 숫자 순서를 구분하는 위치 인코딩이 없다. 숫자 토큰을 재배열하면 attention 출력도 재배열된다.
4. MoE는 모든 칸·숫자 상태에 같은 router/expert를 적용한다. expert는 서로 달라도 숫자별로 고정 배정되지 않는다. 현재 구현에는 token 순서에 따른 capacity 탈락도 없다.
5. DeltaMemory 쓰기는 숫자 축 평균에 의존하므로 숫자를 재배열해도 전역 메모리 S가 같다. 읽기 query는 숫자 축을 따라 재배열된다.
6. 초기 은닉 상태와 `lm_head: D→1` 역시 모든 숫자에 공유된다.

따라서 모든 반복에서

`logits(π(input))[cell, π(digit)] = logits(input)[cell, digit]`

이 성립한다. 답까지 같은 순열로 바꾸면 StableMax CE, focal 가중치, 블록별 CE 평균, expert 빈도 기반 보조 손실도 불변이다. 공유 파라미터 θ에 대해 이 항등식이 성립하므로 `∇θ L(π(input), π(label)) = ∇θ L(input, label)`이다. 정확 연산에서 optimizer 상태와 다른 조건까지 같다면 숫자 치환 여부에 따른 파라미터 업데이트도 같다.

이는 숫자 이름에 따른 불필요한 자유도를 구조에서 제거한다는 의미다. 이전 모델에서 같은 퍼즐을 숫자 치환했을 때 성공/실패가 바뀌던 현상을 logits 수준에서 제거할 수 있다. 정확한 argmax 동점 처리와 유한 정밀도에서의 MoE 경계/누적 오차는 별도 수치 문제다. 이것만으로 퍼즐 자체의 추론 실패가 모두 해결되거나 외삽률이 개선된다는 뜻은 아니다.

### 대칭을 깨는 옵션

`embed()`의 `pe_color = pe[:, D:D+K]`는 숫자별 고정 편향을 만든다. 이 값이 서로 다르면 입력 숫자만 치환해도 채널 편향은 따라 움직이지 않아 등변성이 깨진다. 초기값이 모두 0이어도 제약 없이 학습하면 서로 달라질 수 있다.

`pe_global`처럼 모든 숫자에 같은 D차원 벡터를 더하는 방식은 괜찮다. 이를 원하면 코드에서 color 성분을 제거한 global-only 모드로 분리해야 한다. 현재 구현에서 단순히 `puzzle_emb_ndim=D`로 설정하면 `D:D+K` 슬라이스가 비어 reshape가 실패한다.

숫자별 초기 상태, 숫자별 출력 가중치, 숫자 축 위치 인코딩을 나중에 추가해도 동일한 대칭이 깨질 수 있다. 힌트 표시 자체는 모든 숫자에 같은 규칙을 적용하면 대칭을 보존한다.

## 공간 증강이 여전히 필요한 이유

### 2D RoPE

현재 위치 표현은 행/열 좌표와 상대 거리, 방향을 구분한다. 스도쿠에서는 같은 밴드 안의 행을 교환해도 제약 관계가 보존되지만, 좌표 차이와 RoPE 위상은 달라진다. 전치도 행과 열에 배정된 feature 역할을 바꾸므로 자동으로 보존되지 않는다.

### 학습 가능한 3×3 pooling

`grid=9`, `window=3`이면 9개 창이 스도쿠 박스 9개에 정확히 대응한다는 장점은 있다. 그러나 depthwise convolution의 9개 위치 가중치가 독립적이다. 평균 초기값에서는 박스 안 재배열을 보존하지만, 학습 후 위치별 가중치가 달라지면 보존하지 않는다.

RoPE를 제외한 독립 pooling 검사에서도 박스 내 행 교환 오차가 고정 평균일 때 2.98e-8, 위치별 가중치를 다르게 하면 0.408이었다.

### 전역 메모리를 창 순서대로 지우기

현재는 같은 S에 9개 창의 rank-1 변환을 raster 순서로 적용한다. 일반적으로 `R_a R_b != R_b R_a`이므로 밴드/스택 교환으로 창 순서가 바뀌면 메모리도 달라진다. pooling을 평균으로 고정해도 이것은 남는다. 별도 nonzero S 진단에서 밴드 교환에 따른 update 최대 차이가 0.324였다.

따라서 RoPE만 제거하거나 conv만 평균 pooling으로 바꾸는 것으로 공간 증강을 모두 제거할 수는 없다.

## 공간 증강까지 없애고 싶을 때의 추가 설계

첫 원형 비교 이후의 별도 구조 실험으로 다루는 것이 적절하다.

1. **좌표 대신 스도쿠 관계를 attention에 제공한다.** 같은 칸/행/열/박스 여부로 bias 또는 mask를 만든다. 전치까지 보존하려면 행과 열의 파라미터를 공유한다. 예를 들어 head별 `b_line*(same_row+same_col) + b_box*same_box + b_self*same_cell`은 모든 기존 공간 증강 변환에 불변이다. 이 relation matrix는 이번 검사에서도 오차 0이었다. 행과 열의 bias를 따로 두면 전치가 깨진다.
2. **박스 안에서 순서 없는 집계를 사용한다.** 고정 평균이나 토큰마다 같은 함수 후 합산하는 방식이 가능하다. 3×3 내 위치별 독립 가중치를 두지 않는다.
3. **메모리 갱신도 창 순서에 의존하지 않게 만든다.** 두 선택지가 있다. 전역 S에 대한 erase를 순서 없는 집계로 바꾸거나, 박스마다 S를 따로 두고 공유 규칙으로 갱신한다. 후자는 박스 재배열에 따라 S의 박스 축도 같이 재배열되고, 각 칸이 자기 박스 메모리를 읽게 한다. rank-1 반사 구조는 박스마다 유지할 수 있지만, 원래의 전역 순차 메모리와는 다른 모델이다. 행/열 메모리까지 추가한다면 행과 열의 연산도 공유해야 한다.

위 변경을 모두 결합하면 현재 데이터 로더의 숫자/공간 증강 전체를 구조적으로 대체하는 설계를 만들 수 있다. 관계 bias만 확인한 현재 단계에서 그 전체 모델이 구현·검증됐다고 주장하지 않는다. 새로운 퍼즐의 힌트 배치와 추론 난이도에 대한 일반화는 여전히 학습해야 한다.

## 데이터 로더 변경 시 주의점

현재 `num_aug=0`은 숫자뿐 아니라 공간 증강도 전부 끈다. 실제 첫 실험에서는 기존 로더를 그대로 사용한다. 향후 숫자 증강만 끄는 실험을 추가한다면 `augment_digits`와 `augment_spatial`을 분리해야 한다.

숫자 치환을 끌 때도 기존 RNG의 digit permutation 추출은 소비한 다음 적용할 digit map만 identity로 바꾸면, 동일 seed의 transpose/row/column 변환을 그대로 유지할 수 있다. 그러면 증강 이외의 조건이 덜 섞인다. 기존 고정 pool의 크기, 원본 퍼즐 sampling, optimizer update 수 및 resume cursor는 유지한다.

숫자 순열 9!개에 대한 일관성을 구조가 제공하지만, 현재 로더는 그 전부를 열거해 학습하지 않는다. 따라서 숫자 증강 제거를 곧바로 9!배 학습 시간 절감으로 해석하면 안 된다. 동일 공간 변환에 대한 숫자 치환은 이상적인 연산에서 중복 학습 신호라는 의미다.

### 증강 스크립트에서 숫자 치환 연산만 삭제할 때의 생성 개수

LinearTuring에 보관된 원본 `sudoku_runs/2026-08-26/code/build_sudoku_dataset.py`와 TRM의 `src/trm/data/build_sudoku_dataset.py`를 확인했다. 두 스크립트 모두 `for aug_idx in range(1 + num_augments)` 안에서 정확히 한 쌍을 append한다. 숫자 치환은 `shuffle_sudoku()` 내부에서 그 한 쌍의 값을 바꾸는 연산이고, 별도의 샘플 생성 반복문이 아니다.

따라서 숫자 치환만 identity로 바꾸거나 제거하면, 원본 1,000개 × (원본 1개 + 증강 1,000개) = **1,001,000개 → 1,001,000개**다. 생성 개수 감소는 **0개**, 이 수정만으로 인한 optimizer step 절약도 **0**이다. 생성 수를 줄이려면 `num_aug` 또는 생성 반복문을 별도로 줄여야 한다.

보관한 원본: `runs/new3_sudoku_adaptation/source_build_sudoku_dataset.py`. 아래 중복 제거 집계는 **생성된 풀에 후처리를 추가한 별도 분석**이며, 숫자 치환 연산 삭제만으로 데이터가 얼마나 줄어드는지에 대한 답이 아니다.

### 참고: 생성된 풀에 숫자 치환 중복 제거 후처리를 추가한 경우

`runs/new3_sudoku_adaptation/count_digit_orbits.py`에서 현재 seed=0, 원본 1,000개, 원본당 증강 1,000개 전체를 생성했다. production `_draw_aug_params` / `_apply_aug` 함수를 그대로 사용하고, 입력과 정답을 함께 숫자 정규화해 같은 숫자 치환 궤도에 속하는 예제를 합쳤다. 정답 첫 행을 1~9로 만드는 대응표를 입력에도 적용했으므로 정답이 다른 학습 쌍을 임의로 합치지 않는다.

| 항목 | 개수 |
|---|---:|
| 원본 포함 기존 고정 풀의 서로 다른 학습 쌍 | 1,001,000 |
| 숫자 치환으로만 다른 예제를 합친 뒤 | 1,000,861 |
| 제거되는 중복 | 139 |
| 감소율 | 0.0138861% |

퍼즐 그룹 사이의 추가 중복은 0이고, 남은 개수는 서로 다른 공간 변환 개수와도 일치했다. 현재 풀은 공간 배치마다 숫자 치환을 다수 붙이는 방식이 아니라, 각 증강마다 공간 변환과 숫자 변환을 함께 무작위로 뽑기 때문에 대부분 서로 다른 공간 배치로 남는다.

각 남은 샘플을 같은 횟수 학습하고 배치/샘플당 세그먼트 수를 유지한다는 가정이면, 중복 제거만으로 절약하는 optimizer step 비율도 0.0138861%다. 160,000스텝을 이 비율로 환산하면 약 159,977.8스텝, 약 22.2스텝 절약이다. 반올림·배치 경계에 따라 정수 스텝은 달라지며, 현재 실행 스케줄을 바꾼 것이 아니다.

이것은 **기존 풀의 동일 정보 중복 제거분**이다. 숫자 등변성 덕분에 더 적은 서로 다른 공간 예제로 같은 성능에 도달할 수 있는지는 별도 학습 효율 문제이며, 이 집계로 그 추가 절감량을 계산할 수는 없다. 공간 배치마다 숫자 순열 9!개를 전부 열거한 가상의 완전 증강 풀이라면 숫자 몫집합은 362,880배 작지만, 현재 풀은 그런 구성이 아니다.

## 구현에 반영한 코드 작업

- `initial_carry()`의 hidden/steps/halted와 data를 입력과 같은 device에서 0/초기값으로 할당한다. 원본의 외부 default-device 의존 및 미초기화 텐서를 수정했다.
- `puzzle_emb` property는 `getattr(self.inner, "puzzle_emb", None)`으로 안전하게 반환한다. 현재 스도쿠 설정에서는 숫자별 편향을 차단하도록 `puzzle_emb_ndim=0`만 허용한다.
- 기존 trainer의 h/w/x carry와 새 모델의 hidden/coupling carry가 다르므로 checkpoint 저장·복원 코드를 맞춘다. raw/EMA/optimizer/RNG/데이터 cursor와 router bias를 함께 보존한다.
- MoE의 비활성 expert 마스크를 `probs + bias`로 만든 최종 top-k 점수에도 적용했다. 원본에서는 활성 expert bias가 충분히 음수이면 비활성 expert가 선택될 수 있었다.
- router `pop_counts()` / `apply_balance()` 호출을 optimizer step과 연결한다. activation checkpoint 재계산을 실제 routing 통계에 중복 집계하지 않게 한다. 향후 no_grad-prefix를 도입하면 prefix는 한 번, suffix는 재계산 때문에 두 번 집계되는 비대칭도 피해야 한다.
- 반복은 사용자 지정 기본값인 1세그먼트 × 8블록이다. 8블록 전체에 BPTT를 적용하며 no_grad-prefix는 추가하지 않았다. `ckpt_blocks`는 메모리 절약용 재계산이므로 기울기를 자르는 기능이 아니다. 향후 no_grad 스케줄은 반복 수와 BPTT 길이를 나눠 별도로 실험한다.

## v1 원리를 추가하는 ablation과의 연결

처음 비교할 두 모델은 위 최소 스도쿠 설정을 공통으로 사용하고, 한쪽에만 TxT 관계 메모리를 추가하는 구성이 명료하다. 원래 DeltaMemory는 양쪽에 동일하게 남겨두면 추가한 시냅스 적분의 효과를 볼 수 있다. 공간 대칭까지 바꾸는 실험은 이 비교와 분리한다.

숫자 채널별 `W[B,K,H,T,T]`를 두고 모든 숫자에 같은 쓰기/읽기 규칙을 적용하면 숫자 치환 시 W의 K축도 같이 이동하므로 등변성을 보존한다. 숫자 축을 대칭적으로 평균해 공유 `W[B,H,T,T]`에 쓰는 방식도 가능하지만, 숫자별 관계를 구분하는 능력과 상태 크기가 달라진다. 어느 방식을 쓰는지 명시해야 한다.

v1에서의 부호 있는 관계 적분과 상쇄를 검증하려면, 양수 softmax attention 확률의 EMA만 추가하는 것으로 끝내면 안 된다. signed 관계 신호와 value agreement를 어떻게 만들고 적분할지, 현재 읽기와 과거 메모리를 어떻게 섞을지 명시해야 한다. 새코드3의 q/k score를 쓰는 변형은 v1의 Fourier/STDP 커널 전체를 그대로 복제한 것과도 구분한다.

이 적분 규칙의 파라미터를 숫자별로 분리하지 않고, loss/데이터/반복 예산을 동일하게 두면 숫자 증강을 생략한 상태에서도 해당 ablation을 진행할 수 있다.
