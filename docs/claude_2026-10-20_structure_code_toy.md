# 2026-10-20 구조 코드 토이: 규칙을 g 위의 전이로 표현해 퍼즐 임베딩을 대체할 수 있는가

> **성격**: Claude가 사용자와 설계하고 진행한 토이 실험의 기록이다. 단일 seed다. 결과는 아래 표가 채워지는 대로 갱신한다.

## 0. 질문

- 기존 계보(HRM/URM/TRM과 이 저장소의 Mini-ARC 런)는 과제 규칙을 **퍼즐 임베딩**(과제 ID마다 SGD로 맞춘 자유 벡터)에 담는다.
- 이 실험은 규칙을 **위치 코드 g 위의 전이 연산자**로 표현하고, 시범에서 바로 추론해서 대체할 수 있는지 본다. TEM(Whittington et al. 2020)의 구조 코드 g와 전이 가중치에서 착안했다.

## 1. 과제군 (전제 1~5를 모두 만족하는 토이)

- 4×4 격자, 가장자리가 이어지는 원환. 색은 1~4, 0은 배경.
- 과제 = (T, C).
  - T: 점 연산(D4, 8개) 뒤 순환 평행이동(16개) = 128개.
  - C: 배경을 고정한 색 순열 = 24개.
  - 과제 3,072개. 출력 = C(입력을 T로 옮긴 것).
- 앞에서 정리한 전제와의 관계: 출력 칸마다 입력 칸 하나에서 오고(1), 주소가 내용과 무관하며(2), 격자 전체에 같은 변환이고(3), 색 변환이 색만의 함수이며(4), T가 D4 × 평행이동 안에 있다(5).
- 코드: `toy_g/group.py`(군 정의, 번호 매기기), `toy_g/data.py`(생성기, 정확한 일관성 검사, 분할).

## 2. 데이터

- 모든 샘플은 질의 출력이 시범으로 유일하게 정해질 때만 남긴다. 시범과 일치하는 과제가 모두 같은 질의 출력을 내야 한다. 이상적인 문맥 학습자는 정확할 수 있다는 뜻이다.
- 입력은 칸 3~8개만 색칠한다.
- 고정 인스턴스(`data/gtorus_instances.npz`, seed 0): 과제마다 시범 3쌍 + 시험 1쌍. 시험 출력이 처음 k개 시범으로 정해지는 비율은 k = 1, 2, 3에서 0.663, 0.984, 1.000이다.
- 분할(seed 0):

  | 그룹 | 과제 수 | 뜻 |
  |---|---:|---|
  | 0 train | 2,419 | 학습 과제(평가는 새 입력) |
  | 1 heldout_combo | 269 | T와 C는 각각 학습에 나오지만 그 조합은 처음 |
  | 2 heldout_t | 384 | 처음 보는 변환 16개(점 연산 8종마다 2개, 평행이동 16종 모두 서로 다름)의 모든 색 순열. 점 연산과 평행이동 각각은 학습에 나온다 |

## 4. 결과

시범 3개, 16칸 완답률. 모든 수치는 `toy_g/audit.py`(예측값을 받아 따로 채점)로 다시 계산해서 각 런의 보고값과 일치함을 확인했다(차이 최대 2.6e−8, float32 반올림). 학습에 쓰인 과제는 모든 런에서 그룹 0뿐이다(train_tasks.json의 drawn_by_group).

| 조건 | 학습 과제 | 처음 보는 조합 | 처음 보는 변환 | 비고 |
|---|---:|---:|---:|---|
| 1a 퍼즐 임베딩, 전환적 | 0% | 0% | 0% | 20,750스텝. 학습 쌍 완답 66%(외움), 칸 정확도 49%(입력을 베끼는 수준 47%) |
| 1b 퍼즐 임베딩, 귀납적 | 0% | 0% | 0% | 20,750스텝 |
| 2 재귀 모델, ID 없이 시범을 문맥으로 | — | — | — | 손실이 800스텝부터 1.09에 정체, 완답 0. 5,250스텝에서 중단 |
| 3 설계된 g (확인용) | 100% | 100% | 100% | |
| 4 학습된 g, 코드 공간 합성 (d = 16, 32, 64; 6런) | 100% | 100% | 73~100% | 생성자가 군을 정확히 구현한 런은 100% |
| 4′ 학습된 g, 칸 공간 합성 (d = 32, 4에서 73%였던 초기값) | 100% | 100% | 100% | 읽기 여유 9.29 |

- k = 1, 2(그 시범들로 시험 출력이 정해지는 인스턴스)에서도 같은 양상이다.
- **처음 보는 변환이 100%가 아닌 런의 원인.** 진단에서 128개 후보가 서로 다른 변환을 모두 구현하지 못했다(122~126개). 처음 보는 변환 중 일부만 구현됐고(62~88%), 읽기 여유는 0에 가까웠다. 학습 손실은 학습 변환 112개의 단어만 맞으면 0이 되므로, 생성자 행렬이 위치를 정확히 순열로 옮길 압력이 없다. 그래서 최대 10개를 곱하는 동안 오차가 쌓인다.
- 학습된 생성자는 이름표의 정식 회전·반사가 아닌 다른 원소로 학습되기도 했다. 정확한 런에서는 그래도 128개 단어가 128개 변환에 일대일로 대응했다.
- **효과가 없었던 시도.**
  - 닫힘·단사 보조 손실: 항등 행렬이 사소한 해라서 9런 모두 학습되지 않았다.
  - 칸 공간 합성의 d = 16 + Sinkhorn 색 대응: 학습이 시작되지 않았다(완답 7%).

## 5. 해석과 한계

- 이 토이에서는 퍼즐 임베딩이 하던 일(과제 규칙 담기)을, 과제별 파라미터 없이 시범에서 추론하는 g 위의 전이가 대신했다. 퍼즐 임베딩은 시범 3쌍으로는 학습 과제의 새 입력도 풀지 못했다.
- 처음 보는 규칙으로의 일반화는 생성자 구조에서 온다(구조를 빼면 2~7%). 다만 정도는 학습된 생성자가 군을 얼마나 정확히 구현했느냐에 달려 있다.
- 한계
  - 전제 1~5가 모두 성립하는 과제군이다.
  - 변환이 생성자의 어떤 단어인지(문법)는 주어졌다. perm 색 대응을 쓴 런에서는 색 순열 계열도 주어졌다.
  - 구조 코드는 독립 모듈이고, 우리 재귀 모델 위에 얹은 실험은 아직 없다.

## 6. 퍼즐 임베딩 기준선 점검

1a·1b의 0%가 퍼즐 임베딩의 한계인지, 모델이 이 변환을 아예 못 배우는 것인지 가리려고 데이터를 늘려 다시 돌렸다.

- dense50: 그룹 0 과제마다 새 쌍 50개(120,950쌍, `data/gtorus_id_dense50.npz`). 시험은 3,072개 과제의 시험 쌍. 그룹 1·2의 ID는 학습에 나오지 않으므로 ID 조건에서 0%가 정상이다.
- 칸 정확도 65% 안팎은 전부 배경으로 찍는 수준이다(색칠 칸 3~8개 / 16칸).

### 6.1 같은 하네스에서의 비교 (dense50, d 64, FFN 256, 8블록 × 2세그먼트, 1만 2천 스텝)

| 런 | 모델 | 시험 완답 | 칸 정확도 |
|---|---|---:|---:|
| `gtorus_id_dense50_rope1d_h64_ffn256` | LT, 선형 어텐션, 1D RoPE | 0 / 3,072 | 65.80% |
| `gtorus_id_dense50_urm_h64` | URM 블록 | 2 / 3,072 | 68.48% |

- 두 런은 학습 코드가 같다. `toy_g/urm_harness.py`는 `lt.train`을 고치지 않고 모델 자리에만 URM을 넣는다. 세그먼트마다 갱신, 상태 넘김, 2세그먼트 뒤 레인 교체, stablemax CE, AdamATan2, SignSGD 퍼즐 임베딩, EMA 0.999가 모두 같다. 설정 키도 모두 같다.
- URM 쪽 세그먼트는 원본 `URM_Inner.forward`(`lt/urm_vendor`, URM c14e55f)를 그대로 부른다. 원본과 다른 점은 ConvSwiGLU 대신 SwiGLU, 하네스의 퍼즐 임베딩(원본과 같은 희소 SignSGD 표, 0 초기화), ACT 끔이다. 확인: `toy_g/test_urm_harness.py`.
- 남은 차이는 모델 안에만 있다.

  | | URM | LT |
  |---|---|---|
  | 어텐션 | softmax(q·k/√32), q와 k는 정규화 안 함 | q, k를 길이 1로 정규화한 뒤 Σ(q·k)v. softmax도 합으로 나누기도 없음 |
  | 선형층 초기화 | 절단 정규분포, 표준편차 1/√입력차원 | PyTorch 기본 균등분포, 표준편차 1/√(3·입력차원) |
  | FFN 출력층 초기화 | 위와 같음 | 0 |
  | 분류기 bias | 없음 | 있음 |
  | 정밀도 | 잔차 흐름과 넘기는 은닉 상태가 bf16 | 잔차와 은닉 상태 FP32, 행렬곱 bf16, 어텐션 FP32 |

- 1만 2천 스텝 안에서는 둘 다 거의 배경 수준이다. URM의 칸 정확도가 8천 스텝 무렵부터 조금씩 앞섰다.
- 따라서 1a·1b의 0%가 퍼즐 임베딩 때문인지, 이 하네스와 학습 예산에서 모델이 이 변환을 못 배우는 것인지는 아직 가를 수 없다.

### 6.3 비교 근거가 아닌 런: `toy_g/urm_toy.py`

- 모델은 URM 원본 코드지만 학습 루프는 URM 방식이 아니다. 걸음마다 새 배치를 처음 상태에서 2세그먼트 돌리고 두 손실을 합쳐 한 번 갱신한다(원본 `pretrain.py`는 세그먼트마다 갱신하고 상태를 넘긴다). 손실은 일반 CE, 옵티마이저는 AdamW와 기울기 자르기이고, 일부 런은 퍼즐 임베딩도 AdamW다.
- 같은 스텝에서 하네스보다 데이터와 계산을 두 배 쓴다.
- 이 루프의 dense50 런(`urm_toy_id_dense50_signsgd`, SignSGD 임베딩, EMA 0.999)은 6천 스텝 23, 1만 2천 스텝 38, 1만 8천 스텝 2,154, 2만 6천 스텝 2,371 / 3,072였다(2만 6,250스텝에서 중단). 학습 방식이 달라 6.1의 비교 근거로 쓰지 않는다.
