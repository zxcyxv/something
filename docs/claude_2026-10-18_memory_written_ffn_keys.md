# 2026-10-18 제안: 퍼즐 임베딩 없이 메모리가 FFN 키를 쓰는 구조

사용자의 문제 제기와 Claude의 구체화를 정리한 설계 제안이다. **구현과 실험은 하지 않았다.**
배경 논의는 [claude_2026-10-18_lagrangian_view.md](claude_2026-10-18_lagrangian_view.md)(메모리 = 제약 위반의 승수, FFN = 규칙)에 있다.

---

## 0. 한눈에 보기

- **사용자의 문제 제기:** ARC-AGI로 가면 FFN이 퍼즐마다 다른 제약을 내재화해야 한다. HRM~URM의 퍼즐별 임베딩(입력에 더함)은 너무 약하다. 퍼즐별 성분은 FFN 가중치, 그중 키 쪽에 있어야 한다.
- **입력 임베딩이 약한 이유 (§1):** 입력에 더한 임베딩은 첫 블록에서 FFN 각 슬롯의 문턱(bias)만 바꾼다. 무엇을 검출하는지(키의 방향)는 바꾸지 못한다.
- **관찰 (§2):** 지금 구조도 이미 어텐션 읽기를 통해 FFN 키를 문맥에 따라 저차원으로 바꾸고 있다. 다만 그 경로는 칸 상태와 섞이고, 매 블록 새로 계산되며, 수명이 W와 같다.
- **제안 (§3):** 규칙 메모리 R을 따로 둔다. R은 퍼즐 전체에 걸쳐 느리게 누적되고, FFN 게이트 키에 저차원 보정 ΔW_G = U R B로 직접 들어간다. 퍼즐 식별자는 필요 없다.
- **시험 (§6):** 지금 스도쿠 데이터는 식별자가 하나뿐이다. 그래서 규칙이 다른 스도쿠 변형을 섞어서 시험한다. 처음 보는 변형 조합에서 식별자 방식과 비교한다.

---

## 1. 입력 임베딩은 키의 문턱만 바꾼다

FFN(SwiGLU)의 슬롯 i(중간 차원 I = 2304)에 퍼즐 임베딩 e_p가 입력으로 들어가면 다음과 같다.

    (x + e_p) · k_i = x · k_i + (e_p · k_i)

- 둘째 항은 퍼즐마다 상수인 슬롯별 bias다. 퍼즐이 바꿀 수 있는 것은 "어느 규칙이 더 쉽게 켜지는가"뿐이다. "무엇을 보면 켜지는가"는 바꾸지 못한다.
- bias 벡터는 b = K e_p 꼴이다. 슬롯은 2,304개지만, bias가 움직일 수 있는 방향은 d = 832차원 부분공간으로 제한된다.
- 이 모델에서 e_p는 `LT.injection`을 통해 매 블록 다시 주입되고 h에도 섞인다. 그래서 위 식은 첫 블록에 대해서만 정확하다. 그래도 "공유된 규칙 중 무엇을 고를지 정하는 문맥 벡터"라는 성격은 같다.
- 키-값 메모리로 보면(Geva 외 2021) 키는 조건이고 값은 행동이다. ARC에서 퍼즐마다 다른 것은 주로 조건이다. 그래서 퍼즐별 성분은 키 쪽에 두는 것이 맞다.
- SwiGLU에서 키는 W_G와 W_U 두 개다. 규칙이 켜질지는 게이트가 정하므로, 게이트 쪽 W_G를 우선 대상으로 한다.

## 2. 지금 구조에 이미 있는 경로

정규화를 무시하고 선형화하면 다음과 같다.

    h' ≈ u + W_O · read(u),   read(u) = W · W_Q u
    g  = W_G h' ≈ (W_G + W_G W_O W W_Q) u

- 실효 게이트 키는 K_eff = W_G (I + W_O W W_Q)다. 메모리 W가 이미 FFN 키를 문맥에 따라 바꾸고 있다.
- 이 보정의 rank는 헤드당 D(= 104) 이하이고, 측정상 실제로는 12~16 정도다.
- 이 경로의 한계는 세 가지다.
  1. **칸 상태와 섞인다.** 보정이 잔차 흐름 h'을 거쳐 들어가므로 칸 상태와 같은 공간을 쓴다. RMSNorm도 둘을 함께 정규화한다.
  2. **수명이 W와 같다.** W는 약 8블록짜리 감쇠 메모리다. 제약 위반의 승수처럼 빠르게 바뀌는 사실을 담는 데 맞춰져 있다. 그래서 퍼즐 전체에 걸쳐 유지돼야 할 "이 퍼즐의 규칙"을 담기에는 너무 빨리 잊는다.
  3. **쓰기 대상이 정해져 있다.** W에 쓰이는 것은 v ⊗ k(칸의 사실)다. 규칙을 정하는 별도의 쓰기 신호가 없다.

따라서 제안의 핵심은 새로운 능력을 더하는 것이 아니라 역할을 분리하는 것이다. 빠른 사실 메모리(W)와 느린 규칙 메모리(R)를 나누고, R이 잔차 흐름을 거치지 않고 FFN 키로 직접 들어가게 한다.

## 3. 제안 구조 (v1)

### 3.1 규칙 메모리 R

헤드 그룹마다(또는 하나로) 두며, 크기는 [r × d_c]다(예: r = 64, d_c = 128).

    쓰기:  R ← (1 − η_R) R + η_R · Σ_c α(h_c) β(h_c)ᵀ
    읽기:  g = W_G h' + U · R · (B h')

| 기호 | 크기 | 역할 |
|---|---|---|
| β: d → d_c | 832 × 128 | 조건 특징. 이 칸에서 무엇이 관측되는가 |
| α: d → r | 832 × 64 | 규칙 코드. 그 관측이 어떤 규칙을 시사하는가 |
| B: d → d_c | 832 × 128 | 읽기 쪽 조건 사영. β와 공유해도 된다 |
| U: r → I | 64 × 2304 | 규칙 코드를 게이트 슬롯 보정으로 바꿈 |
| η_R | 헤드별 스칼라 | 느린 누적. 예: 상한 1/64 이하, 퍼즐 전체에 걸쳐 유지 |

- 실효 게이트 키는 W_G + U R B가 된다. 이 보정은 rank r 이하이고, 퍼즐 문맥에 따라 정해진다.
- R은 칸에 대한 합이라 퍼즐 전체의 요약이다. 퍼즐 식별자가 하던 일을 문맥에서 대신한다.
- 파라미터는 약 832 × 128 × 2 + 832 × 64 + 64 × 2304 ≈ 41만 개다. 지금 모델(854만)의 약 5%다.
- 계산은 칸마다 B h'(832 → 128), R·(128 → 64), U(64 → 2304)이다. FFN 본체(832 × 2304 × 3)의 약 10%다.

### 3.2 초기화와 기존 런과의 일치

- U를 0으로 초기화한다. 그러면 학습 시작 시 모델이 기존 구조와 정확히 같다. `ffn_down`을 0으로 초기화하는 것과 같은 관례다.
- 새 파라미터의 난수는 RoPE 다음에 뽑는다. 그래야 다른 가중치의 초기값이 기존 런과 비트 단위로 같다.
- AGENTS.md의 정규화 규칙(어텐션과 FFN 각각에서 잔차를 더한 직후 RMSNorm)은 그대로 둔다. R은 게이트 전활성(pre-activation)에만 더해지고, 잔차 흐름에는 들어가지 않는다.

### 3.3 변형

| 변형 | 내용 | 목적 |
|---|---|---|
| v1-gate | 위 식 그대로, 게이트에만 | 기본 |
| v1-film | 보정을 덧셈 대신 슬롯별 배율로: g ← g ⊙ (1 + U R B h') | 규칙을 켜고 끄는 것만 허용 |
| v1-up | W_U에도 같은 보정 | 키 둘 다 |
| v1-id | R 대신 식별자별 학습 행렬 R_p | 식별자 방식의 상한선. §6의 대조군 |

## 4. ARC로 옮길 때

- **시범 예시(입력 → 출력 쌍)에서 R을 쓴다.**
  - 시범 입력 칸의 특징을 조건 β로, 같은 위치의 출력 특징을 규칙 코드 α로 쓴다.
  - Memory Mosaics(키는 과거, 값은 그 뒤)와 같은 짝짓기다. 여기서는 키가 입력이고 값이 출력이다.
- **시험 입력을 풀 때는 R을 고정하거나 계속 누적한다.**
- **식별자 방식과의 차이:**
  - HRM 계열은 퍼즐 식별자마다 임베딩을 학습한다. 그래서 처음 보는 퍼즐에는 시범 예시로 임베딩을 맞추는 별도의 학습이 필요하다.
  - 평가 퍼즐도 시범 예시로 임베딩을 학습하는 것으로 알고 있으나, 원문으로 확인하지 않았다.
  - R 방식은 순전파 한 번에 시범 예시에서 규칙을 추출한다. 추론 시점의 학습이 필요 없다.
- **필요하면 둘을 합칠 수 있다.** R을 초기값으로 쓰고, 시범 예시에 대한 손실로 R(또는 U)을 몇 스텝 추가로 맞춘다(test-time training).

## 5. 위험과 미결

1. **중복:** §2의 기존 경로가 이미 같은 일을 할 수 있다면 R은 쓰이지 않을 것이다(U ≈ 0에 머묾). U의 노름과, R을 끄는 제거 실험으로 확인한다.
2. **용량:** 퍼즐 하나의 규칙이 rank r에 들어가는가. 스도쿠 변형은 작지만, ARC는 모른다.
3. **쓰기 신호:** R의 쓰기 α, β는 과제 손실로만 학습된다. 규칙과 사실을 가르는 명시적인 신호는 없다. 분리가 실제로 일어나는지 측정해야 한다. 예: R이 퍼즐 안에서는 거의 일정하고, 퍼즐 사이에서만 달라지는가.
4. **수명:** η_R이 너무 느리면 규칙이 늦게 잡히고, 너무 빠르면 W와 다를 바가 없다. W의 η처럼 상한을 둔 학습 파라미터로 한다.
5. **잔차 우회:** 보정이 RMSNorm 뒤 게이트에 직접 더해지므로 크기 제어가 따로 필요할 수 있다. 예: B h'을 정규화하고, U에 작은 초기 스케일을 준다.

## 6. 시험 계획

### 6.1 지금 할 수 있는 진단 (학습 없음)

- §2의 실효 보정 ‖W_G W_O W W_Q‖ / ‖W_G‖를 블록별로 잰다. 기존 경로가 FFN 키를 얼마나 바꾸고 있는지 본다.
- 크면 R은 역할 분리의 의미가 크고, 작으면 기존 경로는 키 보정을 거의 쓰지 않는 것이다.

### 6.2 스도쿠 변형 혼합 (작은 규모)

- **데이터:** 같은 크기(9×9)이고 제약만 다른 변형들입니다.
  - 표준
  - 대각선(X-sudoku): 두 대각선에도 1~9
  - 윈도쿠: 박스 4개 추가
  - 지그소: 박스 모양이 퍼즐마다 다름
- **대조군:**
  - (a) 퍼즐 정보 없음
  - (b) 변형 식별자의 입력 임베딩 (지금 방식)
  - (c) v1-id (식별자별 키 보정)
  - (d) v1-gate (식별자 없이 R)
- **측정:**
  - 변형별 held-out 정확도와 완답
  - 처음 보는 조합(예: 대각선 + 윈도쿠)에서의 성능. 식별자 방식(b, c)은 이 조합에 쓸 식별자가 없다. R은 조건을 조합할 수 있어야 한다
  - 지그소(박스 모양이 퍼즐마다 다름)에서의 성능. 식별자로 표현하기 가장 어려운 경우다
- **판단 기준:**
  - (d)가 (b)보다 낫고 (c)에 가까우면, 문맥에서 규칙을 추출하는 것이 식별자를 대신할 수 있다
  - 처음 보는 조합에서 (d)가 (b), (c)보다 나으면, ARC로 옮길 근거가 생긴다

### 6.3 구현 위치 (예정)

- `lt/model.py`
  - `ModelConfig`: `rule_mem_rank`(r, 0이면 끔), `rule_mem_dim`(d_c), `rule_mem_eta`, `rule_mem_target`('gate' | 'film' | 'up' | 'id')
  - `Block`: α, β, B, U
  - `LT.block_step`: FFN 게이트 계산에 보정 추가
  - 메모리 상태 튜플에 R 추가
- `lt/train.py`: 새 키를 DEFAULTS와 RECIPE_KEYS에 추가. η_R 상한 투영
- `tests/`
  - U = 0이면 기존 모델과 FP64로 같음
  - R의 쓰기가 칸 합 외적의 EMA와 같음
  - 기울기가 새 파라미터에 도달함
- 데이터: 스도쿠 변형 생성 스크립트(`data/`)
