## 코드 감사로 좁힌 범위

확인한 구현 특성:

- 평가 배치마다 새 carry를 만들고 h, W, Z를 초기화한다. 학습 carry를 평가에
  재사용하는 경로는 확인되지 않았다.
- EMA 교환은 raw 값을 백업하고 평가 후 복구한다. 평가 후 train 모드도 복원한다.
- 106k 재개는 raw 가중치·옵티마이저·EMA를 복원한다. 반복 급락 시점에 계속 재개한 것은 아니다.
- 학습률은 처음 2,000스텝 warmup 이후 `1e-4` 상수다. 급락 시점에 예정된 학습률 전환이 없다.
- 실제 런은 batch128, accumulation1, world_size1이다. 조사한 손실 배율에 오류는 확인되지 않았다.

구체적으로 확인한 평가의 차이:

```text
학습되는 puzzle_emb.weights = nn.Buffer, signSGD로 갱신
EMAHelper                  = named_parameters()만 평균
실제 평가 모델              = dense EMA 가중치 + 현재 raw puzzle embedding
```

스도쿠에서 puzzle identifier는 모두 0이므로 이 임베딩은 공통 학습 편향으로 작동한다.
이 혼합은 **v1.1에도 있는 공통 하네스 구현**이다. 따라서 v1.7만의 버그나 급락 원인으로
확정할 수 없다. 같은 시점의 raw/EMA 평가를 분리하는 구체적인 검사 대상이다.

### 이전 Z 정상성 검사의 한계

복구한 `z_probe.py`는 기본적으로 **380k**, 앞 128문제, 32세그먼트를 측정한다.
기울기 검사에는 실제 훈련의 stablemax 손실 대신 일반 cross entropy를 쓴다.
따라서 해당 결과는 **328k 급락 당시의 학습 기울기가 정상**이라는 증거가 아니다.

고정된 유한 파라미터에서 `rho < 1`인 Z 필터와 W의 EMA가 유계여도,
h/Z/W를 함께 갱신하는 전체 재귀가 정답에 수렴하거나 그 정답을 유지한다는 보장은 없다.
노름 발산과 방향·출력의 불안정은 구분해야 한다.

## 다음 원인 검사를 위한 판정 기준

보존된 100k/200k/300k는 EMA 중심 가중치이며 **380k에는 raw도 보존**돼 있다.
Git 전체 경로 이력에서 328k 급락 직전·당시 체크포인트는 찾지 못했다.

같은 체크포인트에서 같은 테스트 문제와 fresh 상태로 raw 전체와 기존 EMA 평가를 비교하면,
그 시점의 성능 저하가 EMA 치환에 따라 생기는지 구분할 수 있다. 380k의 비교를
328k 원인의 증명으로 확대하면 안 된다.

급락 자체를 판정하려면 급락 전·중·후의 같은 시점에서 다음 세 조건이 필요하다.

1. raw 전체 가중치로 고정 평가.
2. 기존 평가 방식: dense EMA + raw 공통 편향.
3. 같은 시간척도로 공통 편향까지 평균한 EMA 평가.

raw는 정상이고 2만 떨어지며 3은 정상이라면 편향을 포함한 EMA의 일관성을 지지한다.
raw는 정상이고 2와 3이 함께 떨어지면 파라미터 평균 자체가 후보로 남는다.
raw도 함께 떨어지면 EMA만으로 원인을 설명할 수 없다.
이후에는 실패 퍼즐의 Z/W/주소 방향과 출력 변화를 급락 전후에서 비교해야 한다.
누락된 과거 가중치·옵티마이저·편향 EMA는 현재 로그로 복원할 수 없다.

gradient 정상성을 보장하지 않는다.

## 정규화 전 y, MLP, Phi와 trace의 직접 관찰

앞의 실행에는 MLP 입력 y를 분리한 hook이 없었다. 이를 추가하고 동일한 raw380k,
seed0, 새 옵티마이저, lr1e-4 조건으로 64스텝을 다시 실행했다. 이전 실행과 매스텝
손실·완답·셀 정확도·dense gradient norm·전체 파라미터 업데이트 기록이 정확히 일치한다.
따라서 아래 관찰을 추가하는 것이 학습 궤적을 바꾸지 않았음을 확인했다.

- 실행: `python lt/probe_training_v17.py --details --out runs/v17_recovery/train_probe_380k_details`
- 분석: `python lt/analyze_training_details_v17.py`
- [블록별 기록](../runs/v17_recovery/train_probe_380k_details/steps.jsonl)
- [분석 수치](../runs/v17_recovery/train_probe_380k_details/detail_analysis.json)
- [그래프](../runs/v17_recovery/train_probe_380k_details/mlp_trace_diagnostics.png)

```text
y = q + attention_output
B(y) = 0.5 * Wd[(Wg y) * (Wu y)]
r = y + B(y)
h = Phi(r) = r / sqrt(1 + ||r||² / 832)
```

64스텝 × 8블록 = 512개 블록에서 y→r→h의 실제 loss gradient를 관측했다.
y와 r에는 이 직렬 경로 밖으로 이어지는 분기가 없다.

| 역전파 경로 | gradient L2 비율의 최솟값 | 중앙값 | 최댓값 | 1 초과 블록 |
|---|---:|---:|---:|---:|
| MLP + residual: grad_y / grad_r | 1.5382 | 1.9006 | 2.2702 | 512/512 |
| Phi: grad_r / grad_h | 0.2816 | 0.3862 | 0.4797 | 0/512 |
| 합성: grad_y / grad_h | 0.6208 | 0.7289 | 0.8786 | 0/512 |

MLP와 residual은 관측 gradient를 키웠지만, **뒤의 Phi까지 포함한 경로는 관측된
모든 블록에서 gradient를 줄였다.** 정규화되지 않은 y에 MLP를 적용한다는 이유만으로
이 경로가 gradient 폭주의 원인이라고 판정할 수 없다.

각 블록에서 셀별 feature L2 norm을 평균하고, 그 512개 평균의 중앙값을 보면:

| 위치 | norm 중앙값 |
|---|---:|
| y: MLP 입력 | 43.3904 |
| B(y): MLP가 더하는 값 | 110.0923 |
| r: Phi 전 | 125.4866 |
| h: Phi 후 | 27.5748 |

개별 y의 최대 norm은 83.7552였다. Phi 후의 상한 sqrt(832)≈28.8444에 비해
y가 큰 것은 실제 관측됐다. 그러나 MLP의 미분이 y에 선형 비례한다는 사실과
합성된 Phi∘(I+B)의 gradient 증폭은 별개다. Phi의 미분은 r의 크기에도 의존한다.

이 비율은 batch·셀·feature 전체 L2이며, **실제 손실 방향**에 대한 결과다.
모든 방향·개별 셀에서 수축한다는 증명이나 Jacobian 최대 특이값 측정은 아니다.
입력 gradient 전달과 MLP 파라미터 변화에 대한 민감도도 구분해야 한다.
또한 q에는 z/W 이월 경로가 합류하므로 grad_q/grad_y를 단순히 attention만의
Jacobian 증폭률로 해석하면 안 된다.

trace 정규화 전 complex norm의 전체 최솟값은 10.4097이었다(eps=0.0001).
이 실행에서는 trace norm이 0에 접근하여 정규화가 특이해지는 현상을 보지 못했다.
trace/address norm 비율의 블록 평균 중앙값은 1.2502, 개별 최댓값은 2.3656이었다.

### v1.7 trace 파라미터의 수학적 위험 조건과 실제 위치

[380k 필터 분석](../runs/v17_recovery/parameter_sensitivity_380k/trace_filter_audit.json)은
입력 u를 외부에서 고정한 선형 trace 필터의 성질을 계산한다. 실제 h/z/W 피드백의
안정성 검사를 대신하지 않는다. rho/omega는 v1.6에서 도입되어 v1.7로 계승된 변수다.

```text
z_next = rho * exp(i*omega) * z + sqrt(1-rho²) * u
H(nu) = sqrt(1-rho²) / [1-rho*exp(i*(omega-nu))]
memory_tau = -1/log(rho)
resonance_gain = sqrt((1+rho)/(1-rho))
```

rho→1이면 기억과 주파수 선택성이 커진다. raw380k의 rho 최댓값은 0.97630,
시간상수 최댓값은 41.68블록, 공명 진폭 배율 최댓값은 9.13이다.
하지만 실제 학습 변수는 rho의 logit이며, unclamped 영역의 고정 주파수 응답은
`abs(d log(H) / d raw_rho) = rho/(1+rho) < 0.5`다. rho에 대한 미분의
특이성을 그대로 raw_rho gradient의 폭주라고 읽으면 틀린다.

omega의 공명점 위상 민감도는 `rho/(1-rho)`이고 raw380k 최대 41.19다.
그러나 같은 채널에서 모든 셀이 동일한 정상상태 주파수 응답 H를 받으면
`z_t * conj(z_n) = abs(H)² * u_t * conj(u_n)`이므로 공통 위상은 상쇄된다.
전체 trace 정규화는 공통 진폭도 제거한다(eps에 따른 작은 차이 제외).
따라서 커널 변화로 이어지는 위험은 채널별 상대 진폭 변화, 셀별 서로 다른 시간 패턴의
상대 위상 변화, 과도상태 등에 있다. 큰 위상 기울기 하나만으로 붕괴를 결론낼 수 없다.

head/channel을 0부터 세면 가장 느린 성분은 head1/channel10이며 omega≈3.1511로
교대 입력에 공명한다. head1/channel23은 rho=.94428, omega=-.00347로 DC 배율5.896이다.
이는 필터 자체의 후보 위치다. 실제 64스텝 손실의 raw-coordinate gradient 제곱합은
오히려 **head0에 rho 98.6375%, omega 99.3708%**가 집중됐다.
높은 rho를 가진 위치와 이 손실에 민감한 위치가 같다고 가정할 수 없다.
이 gradient 집중도는 서로 다른 파라미터화까지 불변인 민감도 척도는 아니다.
