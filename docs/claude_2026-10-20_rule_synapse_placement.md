# 2026-10-20 규칙 시냅스를 LT 어디에 둘 것인가 (후보 설계, 검증 안 함)

> 성격: Claude의 분석과 설계 후보. 학습으로 검증하지 않았다. 근거가 되는 측정은
> `docs/claude_2026-10-20_daily_log.md`와 `docs/claude_2026-10-20_arc_logic_foundations.md` 13절에 있다.

## 0. 출발점

- 확인된 것(독립 모델과 LT의 `rule_syn`):
  - 위치 시냅스 W와 색 시냅스 C를 시범에서 오차 LTP + 문턱 LTD로 쓰면, 시범 3개로 토이 규칙을 복원한다(95%).
  - 문턱이 없으면 25/400이고, 위치·색을 편 64×64 결합 행렬 하나면 0–2/400이다.
- 지금의 `rule_syn`은 band 메모리 옆에 붙인 별도 모듈이다(전용 q/k/v, 격자별 기억). 목표는 기존 부품(bands, Fast FFN)으로 같은 일을 하게 하는 것이다.

## 1. 하나의 텐서로 쓸 수 있는가 (SE-RRM과의 관계)

- SE-RRM(Freinschlag et al., ICML 2026, arXiv 2603.02193)은 상태를 D×I×K(특징 × 위치 × 기호)로 둔다. 위치 축 어텐션과 기호 축 어텐션을 번갈아 걸어서, 구조로 기호 등변을 보장한다. 과제 정보는 과제 유형 임베딩이고, 시범을 문맥으로 읽지 않는다.
- 격자 하나를 텐서 M(위치 코드 P × 색 K)으로 두면, 규칙은 축별 연산 Y = W·X·Cᵀ다. 편 형태로는 vec(Y) = (C ⊗ W)·vec(X), 즉 크로네커 랭크 1이다. 그러므로 "W, C 두 시냅스"는 메모리가 둘이라는 뜻이 아니라, 한 텐서 연산을 축마다 적은 것이다.
- 실패한 것은 축을 편 한 행렬이다(미지수 4,096개에 시범당 벡터 하나).
- 일반화: 연산자를 크로네커 랭크 r인 Σ_j C_j ⊗ W_j로 허용하면, 색마다 다른 위치 규칙(예: "빨강만 민다")도 담는다. 랭크에 비용을 걸면 시범이 요구하는 만큼만 항이 는다.
- 쌍대성: 코드가 정규직교 기저이면, 코드 공간의 W는 칸 공간의 읽기 지도 G·W·Gᴴ(I×I 위치 어텐션)와 같은 대상이다. 그리고 (Σ v kᵀ)q = Σ v(kᵀq)이다. SE-RRM은 이 지도를 층마다 QK 내적으로 다시 계산하고, 우리는 시범에서 쓴 희소한 KV 외적 연산자 하나로 저장한다.

## 2. bands의 시간차 창은 희소성을 주지 않는다

- 흔적곱 메모리를 펼치면 M(n) = Σ_t Σ_{i,j≥0} G(i, j)·v_t(n−i)·k̃_t(n−j)ᵀ이고, G(i, j) = Σ_r γ_r³ Re(c_r z_r^i z̄_r^j)다. 데이터에 대해 선형이다.
- 선형 연산은 특정 시냅스 칸을 골라 0으로 만들지 못한다. 고정점은 시간 가중이 붙은 헤브 합(정리 1의 Ā·P(r) 꼴)이다.
- 창이 고르는 것은 시간차다(어느 쌍을 셀지). 부호가 있는 창의 상쇄(명제 4: 홀수 창은 자기 역원 규칙을 지움)도 데이터와 무관한 선형 상쇄다.
- 망각 |z_r|²는 비례 감쇠(L2 쪽)라서 0을 만들지 않는다.
- 결론: 창은 시간 쪽 선택(적격 흔적)을 맡고, 시냅스 쪽 선택(희소성)에는 문턱이라는 비선형이 따로 필요하다. 흔적곱은 매 블록 새로 계산되므로, 문턱 결과가 쌓일 적분기도 필요하다.

## 3. Fast FFN으로 옮기는 후보

### 3.1 C (색 사상) → Fast FFN: 맞는 배치

- 키: band 메모리를 (W로 옮긴) 질의로 읽은 값, 즉 출처 칸의 내용(읽은 색)이다. 값: 출력 색이다.
- 시범 출력 토큰이 (φ(읽은 색) → 자기 색)을 델타 규칙으로 dW에 쓰면, 그것이 색 사상 κ다. FFN = 키-값 메모리 해석과 맞는다.
- 활성화의 이산성이 도움이 된다. 색이 몇 개뿐이라, φ가 색마다 거의 원-핫으로 갈라지면 키가 이산 표가 된다. 그러면 시범에 나온 색은 최소제곱만으로 정확히 정해진다(문턱 불필요).
- 한계: 시범에 없던 색은 표에 없다. 1절의 색 축 공유 임베딩(SE-RRM)이 해법 후보다.

### 3.2 W (위치 연산자) → Fast FFN: 활성화로는 안 됨

- 필요한 희소성과 활성화가 주는 희소성이 다르다.
  - 필요한 것: 구조 코드 기저에서 연산자 칸의 희소성. 이것이 관찰되지 않은 방향을 채운다.
  - 활성화가 주는 것: 토큰마다 켜지는 은닉 단위의 희소성(φ의 희소성).
- Fast FFN 델타 규칙의 고정점은 dW = VΦᵀ(ΦΦᵀ + λI)⁻¹다. 시범의 φ들이 걸치지 않은 방향에서 dW는 0이다. 즉 "적분만으로는 바깥이 비어 있다"가 φ 공간에서 똑같이 성립한다.
- 예외는 질의 φ가 시범 φ들로 걸쳐지는 경우(특징 재사용)뿐이다. 위치 규칙은 위치 코드에 선형이지 φ에 선형이 아니다.
- 위치 쪽에는 출처 모호성도 있다. 같은 색 칸이 여럿이라 시범 출력 칸의 출처를 모른다(Ā). 이것은 여러 칸·시범에 걸친 공동 제약(희소 연산자)으로만 풀린다. 토큰별 키-값 저장으로는 걸 수 없다.

## 4. 후보 배치

```
질의 칸 o ──W──> 출처 주소 ──band 메모리 읽기──> 출처 내용 ──Fast FFN(C)──> 출력 색
```

- **W:** band 쪽의 적분기. 대역 흔적은 키의 적격 흔적(시간 창)을 맡는다.

  ```
  W ← soft( W + η·(값 − W·키) ⊗ (흔적으로 걸러낸 키 흔적), θ )
  ```

  오차(세 번째 요소)가 Ā를 지우고, 문턱이 지지 집합을 고른다. 문턱이 걸리는 헤드 좌표(키 투영 + RoPE)가 구조 코드로 학습되어야 한다.
- **C:** Fast FFN. 키는 band에서 읽은 내용, 값은 출력 색, 델타 규칙으로 쓴다.
- **순서:** 이론 문서 5절의 블록 일정(구조 전이 → 내용 인출 → 색 대응)과 같다.

## 5. 남는 조건과 검증 계획

- **역할 구분:** 시범 출력 토큰은 자기 짝 입력 격자에서 읽어야 한다(역할 코드나 격자 번호).
- **순서:** W의 읽기가 Fast FFN보다 앞선 블록에서 일어나야 한다.
- **반복 수:** 문턱 고정점에는 FISTA로 100–150회가 필요하고, LT는 순전파당 블록이 16번이다. 블록 안 반복, 또는 지지 집합을 한 번에 고르는 방법(최소 노름 해 + 행별 argmax, 미검증)이 필요하다.
- **검증 순서:**
  1. 손으로 넣은 코드(푸리에 키, 원-핫 값)로 이 배치가 토이 규칙을 복원하는지 확인한다(존재 확인).
  2. 학습시켜서 지금의 `rule_syn`(별도 모듈)과 같은 조건에서 비교한다.
  3. band 메모리를 뺀 판, 별도 모듈 판과 비교해 군더더기를 확인한다.
