## 2. v1.71 후반 저하 분석

자세한 표는 [v1.8 문서 §1](v18.md).

- **학습·테스트 격차:** 앞 512문제 seg16에서 학습 퍼즐은 100k 386 → 200k 425로 오르고, 테스트는 307 → 280으로 내려갔다.
- **파라미터 궤적** (`lt/analyze_params_v171.py`, 마일스톤 20개):
  - weight decay가 없는 스칼라가 100k 이후 한 방향으로 움직였다. 방향은 v1.1·v1.7 쪽이다.
    β의 cos² 0.22 → 0.47, η 0.026 → 0.061, g 0.84 → 1.20, λ 0.30 → 0.25.
  - weight decay 대상 행렬은 수렴하지 않고 1만 스텝마다 계속 회전했다(`wc` 약 44°, MLP 약 38°, `w_sh` 약 24°).
- **파라미터 군 교환** (`lt/probe_param_swap_v171.py`, 100k ↔ 200k):
  - β는 원인이 아니었다. 100k 모델에 200k의 β를 넣으면 오히려 425로 좋아진다.
  - 200k 모델에 100k의 λ·g를 넣으면 seg16이 280 → 304로 100k 수준(307)에 가깝게 회복했다.
  - η·λ·g를 모두 되돌려도 외삽 최고치는 321 → 348로, 100k(410)와의 격차 중 약 30%만 회복했다.
  - 행렬 전체나 스칼라 전체를 교환하면 모델이 붕괴한다.
- **raw와 EMA:** 110k 앞 512문제 seg16에서 raw 168, EMA 308. 테스트 성능의 상당 부분을 EMA 평균이 만든다.
- **반복 동역학:** 미해결 퍼즐 기준 churn(seg128)이 50k 0.164 → 200k 0.065로 줄었다.
  seg16 이후 새로 푼 퍼즐은 135 → 49로 줄었다. 학습이 진행될수록 못 푼 퍼즐이 틀린 상태로 굳는다.

## 3. v1.8 구현

설계·검증은 [v1.8 문서](v18.md).

- **모델:** 헤드별 상수 η·g·λ 대신 칸 상태 q에서 유지 A = exp(−Δ), 쓰기 이득 g, 읽기 보간 λ를 매 블록 생성한다.
  쓰기 쪽은 쌍 대칭으로 결합하고, 게이트는 FP32로 계산한다. β·흔적·agree는 그대로다.
- **하네스 옵션:** `init_from`(v1.71 → v1.8 변환, 데이터 커서 유지), lr 재가열(`lr_rewarm_*`), 후반 감독(`late_sup_*`),
  no-grad 선행 반복(`nograd_every`, `nograd_start`, `nograd_max`).
- **넣었다가 뺀 것:** 가소성 스칼라 전용 lr 배율, 100k 이후 cosine 감쇠.
- **검증:**
  - CPU: selftest 11개 그룹, 단위 테스트 24개.
  - 100k 체크포인트 변환: FP32에서 seg12까지 모든 칸의 예측이 같고, seg128까지 최고 완답도 같다(415 대 415).
  - GPU 스모크: 컴파일된 상태에서 no-grad 깊이 변경까지 확인했다. 이때 `main()` 안의 import 버그를 찾아 고쳤다.

## 4. 학습 실행

v1.71 100k에서 `init_from`, lr은 1e-5에서 1만 스텝 동안 1e-4로 올린 뒤 유지했다. 로컬 RTX 4000 Ada 1장에서 실행했다.
결과 표는 [v1.8 문서 §5](v18.md).

| 구간 (정규 평가 평균, 2048문제) | 원래 v1.71 | B (v1.8) | B+ng (v1.8 + no-grad 반복) |
|---|---:|---:|---:|
| 101k~109k (재가열 중) | 1287 | 1314 | 1353 |
| 111k~123k | 1287 | 1216 | 1254 |

- **B:** 132k에서 중단했다. lr이 1e-4에 도달한 뒤 seg16이 v1.71보다 계속 낮았다(111k~131k 평균 1220 대 1284).
  외삽 최고치는 비슷했다(120k 403 대 393, 130k 373 대 371).
- **B+ng:** 기록 시점(124k)에 실행 중이다. B와 같은 폭으로 하락해 있다(1353 → 1254).
- **게이트 측정 (B, 110k):** 게이트는 이미 선택적이었다. 헤드 평균은 v1.71이 100k→200k에 표류한 방향으로 1만 스텝 만에 이동했다.

## 5. 체스 설계 문서

[체스 설계](chess_search_training.md)를 검토하고 개정했다.

- **원문 대조:** 인용 링크 8개, ChessBench 9M 구성, Gumbel 논문의 예산, Mctx의 `action_weights` 정의를 확인했다.
  파라미터 표는 코드로 다시 셌다.
- **개정:**
  - ChessBench에 모든 합법수의 action-value가 있으므로 지도학습 기본 목표를 soft Q로 바꿨다.
  - 탐색 증류는 교사 라벨이 없는 국면에서 정의했다.
  - 반복 구조의 이점(§3), MCTS의 쓰임과 결합(§6), 같은 블록 예산 비교(§9)를 추가했다.
- **논의:** 반복별 출력 8개는 표본 8개가 아니다. 정책 출력은 분포이고, 분포 하나에서 표본을 여러 개 뽑을 수 있다.
  반복 구조의 이점은 추론 시 반복 증가, 국면마다 다른 계산량, 상태 이어가기, 파라미터 절약에 있다.

## 6. 논의에서 정한 것

- **lr:** HRM–URM 계보대로 warmup 뒤 1e-4로 고정한다. 감쇠나 낮은 lr 실험은 하지 않는다.
- **반복 깊이:** 세그먼트당 8블록은 포화 요인으로 전제한다. TRM은 한 번의 감독당 순방향 42층(역전파 14층)이다.
  v1.1에서 1만 스텝마다 no-grad 반복을 1씩 늘린 실험이 기존 기록을 넘었다는 사용자 보고가 있다(해당 기록은 저장소에 없다).
- **weight decay 제외 파라미터:**
  - 교환 실험으로 부분 지지된다(seg16 하락의 대부분은 λ·g, 외삽 저하의 약 30%).
  - v1.8은 이 파라미터를 없애지 않았다. 게이트 바이어스가 같은 역할로 남았다.
  - Mamba·Mamba2도 Δ 바이어스(`dt_bias`), `A_log`, `D`에 weight decay를 걸지 않는다(공식 코드 확인).
    weight decay는 게이트 바이어스를 특정한 짧은 기억 값 쪽으로 당기므로, 해법은 weight decay가 아니다.
- **v1.9 설계(게이트를 더 늘리는 확장):** 폐기했다.
- **게이트 입력의 정보 부족 가설:** 쌍 관계와 반복 사이 변화 정보가 없는 것은 사실이다.
  다만 게이트가 없는 v1.71도 후반에 하락하므로 근본 원인으로는 보지 않는다. 검증하지 않았다.

## 7. 다음 후보 (구현하지 않음)

- **스칼라 없는 STDP 재구성.** `stdp_fourier.md` §2의 두-흔적 형태를 따르고, 가소성과 커널의 학습 스칼라(약 2,500개)를 없앤다.

  ```text
  흔적   P_t ← ρ_h P_t + (1 − ρ_h) û_t                     헤드별 고정 시정수
  쓰기   G_tn = D_tn · agree_tn · Re[ A₊⟨û_t, P_n⟩ − A₋⟨û_n, P_t⟩ ]   post 지금 × pre 흔적
  누적   w ← (1 − κ_h|G|) ⊙ w + κ_h G                        가중치 의존(soft-bound) STDP
  읽기   J = (1 − |w|) ⊙ a + w,  a = D · Re⟨q̂_t, k̂_n⟩ (q̂ = unit(W_q q))
  ```

  - 변화율(|G|)과 읽기 보간(|w|)이 칸 쌍마다 원리에서 나오므로 게이트가 필요 없다.
  - ψ는 W_q로 흡수하고, θ·α·τ·κ는 헤드별 고정 뱅크로 둔다.
  - v1.71과 같은 함수로 바꾸는 변환이 없으므로 처음부터 학습해 비교해야 한다.
- **게이트 진단:** B 체크포인트에서 게이트 값이 칸의 정착 여부를 추적하는지 측정한다.
- **처음부터 학습 + no-grad 반복:** 세그먼트당 no-grad 8 + grad 8, 또는 1만 스텝마다 +1.
