# 프로토콜 전환안: 시범 쌍을 시퀀스 안에 넣는 LT (in-context ARC)

작성 2026-09-13. 배경: S=10·증강 8·d4 런에서 출력이 seg 8 이후 128 세그먼트까지 한 픽셀도 안 변한다
(`runs/arc_s10/figs/d4_aug8_11k_evolution128.png`). URM 프로토콜은 규칙을 퍼즐 ID 임베딩에 두므로 forward 안에
"내 답이 맞는지 검사할 대상"이 없고, 매 세그먼트 정답 감독은 첫 세그먼트에 답을 내고 유지하는 것을 최적으로 만든다.
LT 의 반복 동역학이 쓰일 자리가 없다. 이 문서는 그 자리를 만드는 최소 변경이다.

## 1. 시퀀스 배치

토큰 = (슬롯 s, 칸 (u,w)).  슬롯은 K 개 시범 쌍 + 질의 쌍 = 2(K+1) 개, 슬롯마다 S×S 캔버스.

```
슬롯:   in₁   out₁   in₂   out₂   in₃   out₃   in_q   out_q(예측)
역할:   D-in  D-out  D-in  D-out  D-in  D-out  Q-in   Q-out
```
K=3, S=10 → T = 8 × 100 = **800 토큰** (지금 URM 900 보다 작다). K=2 → 600.
시범이 K 개보다 적으면 빈 슬롯은 PAD + 역할 "empty".

## 2. 모델 변경 (LT_Inner 세 곳, step/_forward 는 그대로)

**위치.** `pos_u, pos_w` 는 슬롯 안의 칸 좌표. `l1 = ‖Δ_cell‖₁` 도 칸 좌표로만 계산한다 → 다른 슬롯의 *같은 칸* 이 거리 0.
"시범 출력의 같은 자리를 봐라"가 기본 편향이 된다.

**슬롯 위상.** 읽기·쓰기 커널의 위상각에 슬롯별 학습 위상을 더한다:
```
A_t = ψ/2 + θ·pos_t + σ[slot_t],   B_n = −ψ/2 + θ·pos_n + σ[slot_n]       σ ∈ R^{H×p×n_slots}
```
분리형(σ_t − σ_n)이라 `attn_xy` 의 q/k 회전에 그대로 흡수된다 — 비용 0. 슬롯 축의 "상대 위치"를 위상으로 배우는 것이고,
θ·pos 가 하는 일을 이산 축에 대해 하는 것이다. D4LT 에서는 σ 가 공간 방향을 갖지 않으므로 ψ 처럼 헤드 간 공유 → **등변성 유지**
(캔버스 내용을 슬롯마다 같은 g 로 회전하면 Δ_cell → gΔ_cell, σ 는 불변).

**역할 주입.** `injection = embed(x_t) + E_role[slot_t]` (역할 4종 + empty, 자명표현). 퍼즐 ID 임베딩은 **제거**
(`puzzle_emb_ndim=0`; `create_optimizers` 의 sparse 옵티마이저 분기만 손봄).

바뀌지 않는 것: 경계 MLP, Φ, 결합 기억 w (이제 [B,H,800,800] 이고 시범 칸↔질의 칸 관계를 담는다), 세그먼트 carry, 손실 함수.

## 3. 학습 프로토콜

- 샘플 = builder 의 증강 퍼즐 하나(같은 증강이 모든 쌍에 적용돼 있음)에서 쌍 K+1 개를 뽑아 하나를 질의로. **leave-one-out**:
  어느 쌍이 질의가 될지 매 샘플 무작위 → 과제당 학습 신호 (K+1)배.
- 손실: out_q 슬롯의 격자 + 테두리 토큰만 (frame 부호화). 나머지 슬롯 라벨은 −100.
- 세그먼트: 처음엔 URM 과 같이 매 세그먼트 감독. 반복이 안 생기면 뒤쪽 세그먼트 가중을 올리는 변형을 대조.
- 선택: **시범 출력 마스킹** — 확률 p 로 out_k 슬롯 하나를 PAD 로 가리고 그것도 예측하게 한다. 규칙을 시범에도 적용해야 하므로
  "가설이 시범과 맞는가"가 학습 신호가 된다. 반복 동역학을 유도하는 가장 직접적인 장치.

두 평가 설정을 모두 둔다:
| | 학습 과제 | 평가 | 의미 |
|---|---|---|---|
| inductive (주) | training + concept 만 | evaluation 과제는 **처음 보는 과제**, 시범은 context 로만 | 진짜 일반화. HRM/URM 의 전도적 편법 없음 |
| transductive (부) | + evaluation 시범 (leave-one-out) | URM 과 같은 조건 | 기존 곡선과의 연결 |

투표: 질의를 각 증강(색치환 × D4)으로 돌려 역변환·빈도 투표 — `ARCVotes` 그대로. D4LT 면 방향 투표는 항등이라 색치환만.

## 4. 비용 (4090, S=10)

| K | T | 예제당 (fwd+bwd 8블록, 추정) | 20k step × batch 16 |
|---|---|---|---|
| 2 | 600 | ~14 ms | ~1.2 h |
| 3 | 800 | ~25 ms | ~2.2 h |

w 가 [B,H,T,T] 라 배치 16 에 T=800 이면 w 만 0.3 GiB, 활성화 포함 ~15 GiB 예상 → 배치 8~16.

## 5. 구현 목록 (lt/ 수정 없음, arc_analysis/ 안)

1. `lt_ctx.py`: `CtxInner(LT_Inner)` — 위치 버퍼(슬롯 타일), `kernel()` 에 σ, `injection()` 에 역할 임베딩, ID 임베딩 없음.
   `D4CtxInner` 는 σ 공유·역할 자명표현. `equivariance_check.py` 에 슬롯별 회전 검사 추가.
2. `ctx_data.py`: builder 출력(`train/all__*.npy`, `puzzle_indices`) 에서 (K+1) 쌍 샘플러, 마스킹, 라벨. 평가 배치 생성.
3. `train_arc_ctx.py`: 학습 루프는 `train_arc.py` 의 것을 재사용 (carry·EMA·AdamATan2·체크포인트), 데이터·모델·평가만 교체.
4. 검사: 슬롯 등변성, leave-one-out 라벨이 입력에 새지 않음, 평가 질의 정답이 학습에 없음(inductive), 재개 비트 일치.

예상 작업량 1~2 일. 첫 실험은 K=2, S=10, d4, inductive, 20k step.

## 6. 판정 기준

- 1차 관문: 세그먼트별 출력 진화 그림에서 **seg 8 이후에 바뀌는 픽셀이 있는가** (지금은 0). 있으면 반복이 쓰이기 시작한 것.
- 2차: seg16 → seg64 에서 완전 일치가 늘어나는가 (Sudoku 의 외삽 기준과 동일).
- 3차: inductive pass@2 가 0 을 벗어나는가 — 이건 이 모델이 "규칙을 시범에서 읽는다"는 뜻이고, URM 설정에서는 원리적으로
  측정할 수 없던 값이다.
- 위험: 위상 주소 기제가 "시범에서 본 변환을 질의에 적용"을 표현할 수 있는지 미지수. 1차 관문에서 안 움직이면 시범 마스킹(§3) 을 켜고,
  그래도 안 되면 LT 의 커널이 이 과제군에 맞지 않는다는 결론이 된다.
